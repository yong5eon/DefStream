# JavaScript 개발

## 기본 원칙

- 공통 개발 지침과 프로젝트의 기존 프레임워크·도구·코드 관례를 따른다. 요청 없이 프레임워크나 의존성을 도입하거나 교체하지 않는다.
- 대상 런타임과 빌드 환경에서 지원하는 JavaScript 기능을 확인한다. 호환성이 필요한 경우 추측으로 문법을 제한하거나 별도 변환 계층을 추가하지 말고 프로젝트 설정을 따른다.
- `.mjs`, `.cjs`, `package.json`의 `"type"` 등으로 정해지는 모듈 형식과 프로젝트의 실행 방식을 확인하고, 해당 형식의 import/export 또는 CommonJS 계약을 일관되게 따른다. 불필요한 모듈 형식 변환이나 상호운용 래퍼를 만들지 않는다.

## Node.js 애플리케이션과 스크립트

- 명령행 인자, 환경 변수, 파일 경로와 외부 프로세스 등 외부 입력을 경계에서 해석하고 검증한다. 요청하지 않은 파일 덮어쓰기, 삭제, 네트워크 통신 등 부작용을 추가하지 않는다.
- 실행 진입점은 입력 처리, 핵심 동작 호출과 종료 결과가 드러나게 구성한다. 입력 파싱, 업무 규칙과 출력·파일 처리를 분리하되, 단순 스크립트에 불필요한 계층이나 래퍼를 만들지 않는다.
- 파일·스트림·프로세스 등 자원은 사용한 코드의 책임과 생명주기에 맞게 정리한다. 비동기 작업이 끝나기 전에 프로세스가 종료되거나 실패가 성공 종료로 보고되지 않도록 실행 계약을 확인한다.
- 스크립트가 파일이나 외부 시스템을 변경하면 대상, 입력, 출력과 부작용이 실행 흐름에서 명확해야 한다. 재시도, 폴백, 광범위한 복구는 명시된 요구나 확인된 필요가 있을 때만 추가한다.

## 브라우저와 UI

- UI 구성요소, 화면 상태, 도메인 동작과 브라우저 입출력의 책임을 필요한 범위에서 구분한다. 단순한 화면 동작에 불필요한 계층이나 추상화를 추가하지 않는다.
- 상태의 소유 위치와 갱신 흐름을 명확히 한다. 같은 상태를 여러 곳에서 독립적으로 보관해 서로 다른 값이 되지 않도록 하며, 화면 갱신은 프로젝트의 기존 UI 패턴을 따른다.
- 이벤트 처리기는 이벤트 경계에서 입력을 읽고 적절한 동작으로 연결한다. 처리기에서 무관한 정책·변환·상태 관리를 함께 수행하지 않으며, 호출만 연쇄 위임하는 계층을 만들지 않는다.
- DOM 요소와 이벤트 리스너는 생성·등록한 구성요소의 생명주기와 연결해 관리한다. 화면에서 제거되거나 동작이 끝날 때 필요한 리스너와 자원을 정리하고, 동일 처리기가 중복 등록되지 않게 한다.
- 외부 데이터와 사용자 입력을 DOM에 표시할 때 프로젝트에서 사용하는 안전한 텍스트·렌더링 API를 따른다. 문자열을 실행 가능한 HTML로 취급하거나 검증 없이 삽입하지 않는다.

## 비동기 처리와 오류

- 비동기 작업의 완료·실패·취소 처리는 호출자의 계약과 작업 생명주기에 맞춘다. 브라우저 UI에서는 요구사항에 따라 로딩·성공·실패 상태와 필요한 오류 정보를 화면에 전달한다.
- 취소·화면 전환·재요청으로 오래된 비동기 결과가 현재 UI 상태를 덮어쓸 수 있는 경우, 프로젝트의 기존 방식으로 결과 반영 시점을 관리한다. 실제 위험이 없는 곳에 불필요한 취소·동시성 계층을 추가하지 않는다.
