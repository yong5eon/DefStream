# DefStream 소스코드 작성 지침

## 목적과 적용 범위

DefStream은 한국어 사용자뿐 아니라 전 세계 사용자를 대상으로 한다. 소스코드를 읽거나 실행 결과를 접하는 사용자가 공통으로 이해할 수 있도록 코드 안의 설명과 진단 문구는 영어로 작성한다.

프로젝트의 Python 소스, 테스트, 샘플과 보조 스크립트를 작성·수정할 때 적용한다. 다른 언어의 소스를 다루는 경우에도 같은 언어 정책을 따른다.

## 코드 내 언어 정책

- 모듈·클래스·함수·메소드의 독스트링은 영어로 작성한다.
- 주석과 TODO 설명은 영어로 작성한다. 언어 규칙을 적용하기 위해 불필요한 주석이나 독스트링을 추가하지 않는다.
- 예외를 발생시킬 때의 오류 메시지, 경고, 로그, CLI 도움말과 사용 안내 등 프로젝트가 생성하는 진단 문구는 영어로 작성한다.
- 샘플의 설명용 출력과 테스트 실패 시 제공하는 설명 문구도 영어로 작성한다.
- API·식별자·패키지 이름·프로토콜 용어는 원래 표기와 저장소 명명 규칙을 유지한다.

## 예외와 다른 지침의 관계

- 국제화·인코딩·다국어 처리를 검증하는 테스트 데이터, 사용자 입력과 원문 보존이 필요한 외부 자료까지 영어로 바꾸지는 않는다.
- 명시적으로 현지화하는 콘텐츠는 해당 언어·번역 계약을 따른다. 라이브러리 진단 문구와 사용자가 제공하는 메시지를 구분한다.
- 이 프로젝트의 코드 내 문구에는 공통 지침의 한국어 독스트링·주석 작성 규칙 대신 이 영어 정책을 적용한다.
- 이 지침 문서와 개발 과정의 사용자 설명은 한국어로 작성한다. README·매뉴얼 등 독립 문서의 언어는 해당 문서 지침을 따른다.

## 변경과 검증

- 새로 작성하거나 변경하는 코드 내 문구에 이 정책을 적용한다. 별도 요청 없이 기존 코드 전체를 일괄 번역하지 않는다.
- 기존 오류 문구를 바꿀 때는 메시지를 확인하는 테스트와 관련 문서를 함께 검토한다. 예외 타입, 오류 코드와 기존 동작을 번역 목적으로 바꾸지 않는다.
