# 요구사항 명세서: Inspector 확장 이름 변경

## 출처

- 이슈: [ISSUE.md](./ISSUE.md)
- 변경 유형: 일반 변경

## 목적

Inspector 확장의 이름을 역할에 더 자연스럽게 맞춰 사용자가 이해하고 선택하기 쉽게 한다.

## 범위

- Inspector의 `Dashboard` 확장 이름을 `Status`로 변경한다.
- Inspector의 `HealthCheck` 확장 이름을 `Ping`으로 변경한다.
- 대시보드 URL을 `/status`로, 상태 확인 URL을 `/ping`으로 변경한다.
- 이름 변경에 필요한 공개 API 노출, 문서, 샘플 및 관련 테스트를 일관되게 반영한다.

## 확정 요구사항

| ID | 요구사항 |
| --- | --- |
| RQ-1 | 기존 `Dashboard` 확장은 `Status`라는 이름으로 사용할 수 있어야 한다. |
| RQ-2 | 기존 `HealthCheck` 확장은 `Ping`이라는 이름으로 사용할 수 있어야 한다. |
| RQ-3 | 이름 변경으로 각 확장의 기존 동작과 응답 계약이 달라져서는 안 된다. `Status`는 기존 대시보드의 HTML 및 지표 JSON 응답을 제공하고, `Ping`은 기존 상태 확인 결과와 HTTP 응답을 제공한다. |
| RQ-4 | `Status` 대시보드의 요청 경로는 `/status`로, `Ping` 상태 확인의 요청 경로는 `/ping`으로 한다. |
| RQ-5 | 패키지에서 제공하는 공개 가져오기 경로, 문서, 샘플 및 관련 테스트에서 새 이름과 URL을 일관되게 사용한다. |

## 제약사항

- 이슈는 확장 이름과 요청 경로 변경을 요청하므로 그 외의 기능 추가나 응답 형식 변경은 범위에 포함하지 않는다.
- `Status`와 `Ping`은 기존 확장의 기능 및 설정을 이어받아야 한다.
- 요청 경로는 이슈의 명시적 변경 사항에 따라 `/status`와 `/ping`으로 변경한다.
- 이전 공개 이름(`Dashboard`, `HealthCheck`)과 이전 모듈 경로는 호환 별칭으로 유지하지 않는다.

## 인수 기준

1. `DefStream.Inspector.Extensions`에서 `Status`와 `Ping`을 가져와 Inspector 확장으로 등록할 수 있다.
2. `Status`는 기존 대시보드와 동일하게 HTML 및 지표 JSON 응답을 제공한다.
3. `Ping`은 기존 상태 확인과 동일하게 정상일 때 성공 응답을, 비정상일 때 서비스 불가 응답을 제공한다.
4. `Status`는 `/status`, `Ping`은 `/ping`에서 응답한다.
5. 샘플, 문서, 공개 내보내기 및 관련 테스트에 새 이름이 반영된다.

## 결정 사항

- 이전 이름을 호환 별칭으로 제공하지 않고 `Status` 및 `Ping`으로 대체한다.
- 클래스명에 맞춰 모듈 경로와 대시보드 HTML 리소스도 `Status`로 변경한다.
- 확장 고유 로거 이름과 로그 메시지도 새 클래스 이름을 사용한다.
