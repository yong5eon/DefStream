## 1. 소스 및 배포 통합

- RabbitMQ 소스 11개와 Redis 소스 8개를 `src/Broker/Implements` 아래 각 브로커 디렉터리로 이관했다.
- 기존 로컬 심볼릭 링크를 실제 디렉터리로 교체하고, 브로커 소스를 제외하던 Git 무시 규칙을 제거했다.
- 브로커 소스는 원본과 동일하게 유지했다. 공개 import 경로는 `DefStream.Broker.Implements.RabbitMQ` 및 `DefStream.Broker.Implements.Redis`이다.
- `setup.py`의 RabbitMQ extra는 `pika>=1.3.2`, Redis extra는 `redis>=5.1.1`을 설치한다. 기존 별도 어댑터 패키지 의존성은 제거했다.
- 기본 배포본에 두 구현체를 모두 포함하되, 브로커 클라이언트는 기본 필수 의존성으로 추가하지 않았다.

## 2. 전체 테스트 및 CI 이관

- RabbitMQ 테스트 파일 8개, Redis 테스트 파일 4개를 `tests`로 이관했다.
- 기존 테스트 메서드 RabbitMQ 70개, Redis 47개가 모두 이관됐음을 원본과 대조했다. 배포 워크플로 테스트도 각 파일을 이관해 통합된 워크플로를 검증한다.
- 파일명 충돌을 피하도록 필요한 테스트 파일명에 브로커 접두사를 추가했다. 샘플 로깅 테스트의 경로를 새 위치로 변경했다.
- 기본 설치와 각 extra의 의존성 및 import 독립성, 배포본의 브로커 소스 포함 여부를 검증하는 테스트를 추가했다.
- CI에서 외부 어댑터 저장소 체크아웃, 의존 저장소 ref 결정, 별도 어댑터 빌드를 제거했다.
- DefStream 하나의 wheel을 빌드·설치하고 `tests` 전체를 실행한다. Python 3.9~3.14 매트릭스와 RabbitMQ·Redis 서비스는 유지했다.
- 두 브로커 통합 테스트의 활성화 환경변수를 설정해 서버 의존 테스트가 자동 실행되도록 구성했다.
- CI에 기본 설치·RabbitMQ 단독·Redis 단독 설치를 별도 가상환경에서 검증하는 단계를 추가했다.
- CI 파일 자체의 변경도 테스트 실행 조건에 포함하고 관련 회귀 테스트를 보완했다.

## 3. 샘플 및 사용 문서

- RabbitMQ 샘플 3개를 `samples/Broker/RabbitMQ`, Redis 샘플 2개를 `samples/Broker/Redis`로 원본 그대로 이관했다.
- 두 브로커의 송수신, 연결 설정, 로깅, Worker, 메시지 정산, 운영 제약과 브로커별 기능 안내를 한국어·영어 메인 README로 옮겼다.
- 별도 패키지 설치 안내를 단일 패키지 및 extra 선택 방식으로 변경했다.
- 기존 어댑터 배포 종료, 프로젝트 삭제 예정, 하위 호환성 미지원 및 기존 설치 환경의 재설치 주의사항을 안내했다.
- 기존 어댑터 프로젝트의 원본 파일은 수정하거나 삭제하지 않았다. 실제 외부 프로젝트 삭제나 패키지 배포 작업은 수행하지 않았다.

## 5. CI 로깅 테스트의 비결정적 실패 수정

- `Queue.pop()` 로그 개수 검사에 다른 Queue 객체의 소멸자 로그가 섞일 수 있음을 확인했다. 브로커 전체 로거를 수집하던 테스트가 객체 수거 시점에 따라 실패했으며, 메시지 수신 동작의 오류는 아니었다.
- 해당 테스트의 Queue 인스턴스에 전용 로거를 지정하고 그 로거만 수집하도록 변경했다. 제품의 로깅 동작이나 정확히 두 로그를 요구하는 검증 조건은 변경하지 않았다.
- 대기 중 순환 참조를 가진 별도 Queue 객체를 강제 수거하도록 구성해, 지연 정리 로그가 발생하는 조건을 회귀 검증에 포함했다.
- Python 3.13 격리 환경에서 기존 수집 방식이 정리 로그를 포함해 `3 != 2`로 실패함을 재현했다. 수정한 RabbitMQ 로깅 테스트 14개는 30회 반복해 총 420개 모두 통과했다.
- 이 수정에 대해 전체 테스트 및 GitHub Actions 원격 재실행은 수행하지 않았다.
