# 브로커 구현체 통합 작업 기록

## 목적

[요구사항](./REQUIREMENTS.md)에 따라 분산된 브로커 구현체와 검증·사용 안내를 DefStream 프로젝트로 통합한다.

## 조사 및 분석

- 본체와 별도 어댑터 프로젝트의 패키징 설정, 공개 export, 테스트, 샘플 및 CI 구성을 확인했다.
- 본체의 브로커 디렉터리가 외부 프로젝트 소스를 가리키는 심볼릭 링크이며, Git에서 무시되고 있음을 확인했다.
- 기존 CI가 세 저장소를 체크아웃하고 별도 패키지를 빌드하는 구조임을 확인했다.
- 사용자 확인을 통해 단일 패키지 배포, 기존 어댑터 배포 종료, 호환성 미지원, 전체 테스트 자동 실행을 확정했다.
- 공개 import 경로 및 extra를 통한 클라이언트 선택 설치는 유지하기로 확정했다.

## 검증 환경 및 수행 내용

- 세션 전용 가상환경을 사용해 기존 어댑터 배포 패키지 없이 통합 DefStream을 설치했다.
- Docker Desktop을 시작하고 작업 전용 RabbitMQ 컨테이너를 생성했다. Redis는 기존 로컬 컨테이너를 사용했다.
- RabbitMQ 상태 확인과 Redis PING 응답을 확인한 뒤 두 통합 테스트 활성화 환경변수를 지정했다.
- Windows의 기본 출력 인코딩으로 Worker 배너 출력이 실패하여, 제품 코드를 변경하지 않고 검증 환경에 `PYTHONUTF8=1`을 지정했다.
- Python 3.13과 최소 지원 버전인 Python 3.9에서 전체 테스트를 실행했다.
- wheel·sdist 안의 브로커 파일을 원본과 대조하고, 원본 테스트 메서드 및 샘플의 누락 여부를 확인했다.
- 기본 설치·각 브로커 단독 설치를 별도 가상환경에서 검증해 선택하지 않은 클라이언트 및 기존 어댑터 배포 패키지 없이 import할 수 있음을 확인했다.
- 에디터 테스트 도구는 테스트를 발견하지 못해, 가상환경의 `unittest`를 직접 사용했다.
- 검증 후 작업 전용 RabbitMQ 컨테이너를 중지·제거했다. 기존 Redis 컨테이너와 어댑터 프로젝트는 유지했다.

## 결과 및 한계

- 상세 구현 및 실제 검증 수치는 [구현 기록](./IMPLEMENTS.md)에 기록했다.
- GitHub Actions 원격 실행 및 실제 패키지 배포는 수행하지 않았다.
- 기존 어댑터 프로젝트 삭제는 수행하지 않았다.
