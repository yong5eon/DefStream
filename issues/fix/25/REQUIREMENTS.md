# 브로커 구현체 통합 요구사항

## 1. 목적

RabbitMQ와 Redis 브로커 구현체가 DefStream 본체와 별도 프로젝트로 분리되어 있어 발생하는 버전 정합성 및 테스트·기능 변경의 관리 부담을 줄인다. 브로커 구현체의 소스와 검증을 DefStream 프로젝트에서 함께 관리하여 변경을 한 흐름으로 통합한다.

## 2. 현황과 문제

- DefStream, DefStream-RabbitMQ, DefStream-Redis가 별도 프로젝트와 배포 패키지로 관리된다.
- 본체의 `DefStream[RabbitMQ]`, `DefStream[Redis]` extra는 각각 별도 어댑터 배포 패키지를 설치한다.
- 어댑터별 코드와 테스트가 각 프로젝트에 있어 본체와 브로커 간 변경·테스트를 조율해야 한다.
- 두 어댑터는 현재 `DefStream.Broker.Implements.RabbitMQ`와 `DefStream.Broker.Implements.Redis` import 경로를 사용한다.

## 3. 범위

### 포함

- RabbitMQ 및 Redis 브로커 구현체를 DefStream 프로젝트의 소스 관리 범위로 통합한다.
- RabbitMQ 및 Redis 프로젝트의 전체 테스트를 DefStream 테스트 디렉터리로 이관하고, DefStream CI 워크플로(`ci.yml`)에서 자동 실행한다.
- RabbitMQ 및 Redis 샘플을 각각 `samples/Broker/RabbitMQ`와 `samples/Broker/Redis`로 이동한다.
- 각 브로커의 사용 방법 안내를 DefStream의 `README.md`와 `README.en.md`로 옮겨 작성한다.
- 기존 브로커 기능과 통합 후의 공개 API, import 경로 및 사용 문서를 기준으로 통합 완료 여부를 검증한다.
- 설치 및 의존성 안내를 통합된 배포 구조와 일치하도록 갱신한다.
- 브로커 구현체를 DefStream 단일 배포 패키지에 포함하고, 기존 어댑터 패키지 배포 종료와 프로젝트 삭제 예정 사실을 안내한다.

### 제외

- RabbitMQ 또는 Redis의 기능을 추가·삭제하거나 두 브로커의 기능 차이를 없애는 변경.
- 브로커 서버의 운영·배포·구성 변경.
- 기존 동작이나 공개 API를 통합과 무관하게 재설계하는 변경.

## 4. 요구사항

### RQ-1. 구현체의 단일 소스 관리

RabbitMQ와 Redis 구현체의 정본 소스는 DefStream 프로젝트 안에서 관리해야 한다. 구현체 수정이 별도 어댑터 프로젝트의 소스에 추가로 반영되어야 하는 구조를 통합 후 유지하지 않는다.

### RQ-2. 본체와 함께 수행하는 테스트

RabbitMQ 및 Redis 프로젝트의 전체 자동화 테스트를 DefStream 테스트 디렉터리로 이관한다. 단위 테스트, 통합 테스트 및 배포 워크플로 검증을 포함해 기존 테스트의 검증 항목을 빠짐없이 이관하며, 통합으로 달라진 경로·패키지·워크플로에 대한 검증은 새 구조에 맞게 수정한다.

두 브로커의 이관된 전체 테스트는 DefStream의 CI 워크플로(`ci.yml`)에서 자동 실행해야 한다. 브로커 서버가 필요한 테스트는 CI에 RabbitMQ·Redis 서비스와 실행 환경을 구성하여 실제 실행한다. 파일만 옮기거나 수동·선택 실행으로 남기는 것, 서비스 미구성으로 테스트를 건너뛰는 것은 이 요구사항을 충족하지 않는다.

### RQ-3. 브로커 기능 보존과 통합 후 API 검증

기존 배포 구조 및 공개 API에 대한 하위 호환성은 지원하지 않는다. 다만 호환성 미지원은 기존 브로커 기능을 임의로 제거하거나 통합과 무관한 API 재설계를 수행한다는 의미가 아니다. 다음 기능은 통합 후의 공개 API와 샘플을 기준으로 검증한다.

- 연결과 설정, 자원 선언·삭제, 발행·수신 및 메시지 정산.
- 구독·소비자 동작과 DefStream Worker와의 연동.
- RabbitMQ가 제공하는 Exchange 라우팅 및 RPC 기능.
- Redis Streams가 제공하는 스트림·소비자 그룹 기능과 기존 제약.
- 공개 import 경로 `DefStream.Broker.Implements.RabbitMQ` 및 `DefStream.Broker.Implements.Redis`와 사용 예제의 일치 여부.

통합 후에도 위의 공개 import 경로를 유지한다. 이는 별도 호환 계층을 제공한다는 뜻이 아니며, 기존 어댑터 배포 패키지에 대한 호환성 지원과는 구분한다.

### RQ-4. 브로커별 의존성 선택성 유지

통합만으로 사용하지 않는 브로커의 클라이언트 라이브러리를 코어 전용 설치에 필수화하지 않는다. 사용자가 선택한 브로커의 의존성을 설치하는 방법은 문서에 명확히 안내한다.

- `DefStream` 기본 설치에는 브로커 클라이언트를 필수 의존성으로 포함하지 않는다.
- `DefStream[RabbitMQ]`는 `pika`를 설치한다.
- `DefStream[Redis]`는 `redis`를 설치한다.
- `DefStream[RabbitMQ,Redis]`는 두 클라이언트를 모두 설치한다.
- 두 브로커의 구현 소스는 extra 선택 여부와 관계없이 DefStream 배포 패키지에 포함한다. 코어 및 선택한 브로커를 사용할 때 선택하지 않은 브로커 클라이언트의 부재로 import가 실패하지 않아야 한다.

### RQ-5. 사용자 문서 정합성

DefStream의 한국어·영어 사용자 문서와 관련 샘플은 통합 후 실제 설치 방법, import 경로, 브로커별 기능 및 제약과 일치해야 한다. RabbitMQ 및 Redis의 설치·연결 설정·기본 사용 방법은 `README.md`와 `README.en.md`에서 안내한다. 두 언어 문서는 같은 사용 시나리오와 핵심 정보를 제공해야 한다. RabbitMQ 샘플은 `samples/Broker/RabbitMQ`, Redis 샘플은 `samples/Broker/Redis`에 둔다. 샘플 이동으로 바뀌는 문서·스크립트·테스트 참조 경로도 함께 갱신한다. 더 이상 유효하지 않은 별도 패키지 설치·관리 안내는 갱신한다.

### RQ-6. 단일 패키지 배포 및 기존 프로젝트 종료

RabbitMQ와 Redis 구현체는 DefStream 단일 배포 패키지에 포함한다. `DefStream-RabbitMQ`와 `DefStream-Redis` 패키지의 별도 배포는 종료하며, 두 기존 프로젝트는 삭제 예정이다. 통합된 DefStream의 설치·실행에 기존 어댑터 패키지나 프로젝트가 필요하지 않아야 한다. 브로커 선택 설치가 기존 어댑터 패키지를 의존성으로 설치하지 않도록 변경한다.

기존 패키지에 대한 호환 릴리스나 호환성 지원은 제공하지 않는다. 사용자 문서에는 단일 패키지 설치 방법, 별도 어댑터 배포 종료, 기존 프로젝트 삭제 예정 및 하위 호환성 미지원 사실을 명시한다. 프로젝트의 실제 삭제는 이 명세서 작성 작업에서 수행하지 않는다.

## 5. 제약 및 호환성 기준

- 코어만 사용하는 기존 설치가 특정 브로커 클라이언트에 불필요하게 종속되지 않도록 한다.
- 기존 어댑터 배포 패키지에 대한 하위 호환성은 지원하지 않으며, 이를 위한 호환 패키지나 별칭을 추가하지 않는다. 공개 import 경로는 RQ-3에 명시한 경로를 그대로 사용한다.
- 브로커별 의미 차이와 지원 범위는 유지한다. 특히 Redis Streams에 RabbitMQ 전용 Exchange·RPC 기능이 있다고 오인하게 해서는 안 된다.
- 브로커 서버와 통신이 필요한 검증과 서버 없이 실행 가능한 단위 테스트를 구분하고, 필요한 서비스·환경을 검증 안내에 명시한다.

## 6. 인수 기준

- [ ] RabbitMQ 및 Redis 구현체의 정본 소스가 DefStream 프로젝트에 포함되어 있다.
- [ ] RabbitMQ 샘플이 `samples/Broker/RabbitMQ`, Redis 샘플이 `samples/Broker/Redis`에 있으며 이전 위치를 참조하는 문서·스크립트·테스트가 갱신되어 있다.
- [ ] `README.md`와 `README.en.md`에서 RabbitMQ 및 Redis의 설치·연결 설정·기본 사용 방법을 각각 안내하고, 두 문서의 핵심 사용 정보가 일치한다.
- [ ] RabbitMQ 및 Redis 프로젝트의 전체 테스트가 검증 항목의 누락 없이 DefStream 테스트 디렉터리로 이관되어 있다.
- [ ] 두 브로커의 전체 테스트가 DefStream CI 워크플로(`ci.yml`)에서 자동 실행되며, 서버 의존 테스트도 서비스 미구성에 따른 건너뛰기 없이 실제 실행된다.
- [ ] 통합으로 경로·패키지·워크플로가 달라진 테스트는 새 구조를 검증하도록 수정되어 있다.
- [ ] `DefStream.Broker.Implements.RabbitMQ` 및 `DefStream.Broker.Implements.Redis` 경로로 import할 수 있고, 대표 사용 예제가 문서와 일치하며 정상 동작한다.
- [ ] 코어 전용 설치와 각 브로커 선택 설치의 의존성 동작이 문서와 일치한다.
- [ ] 기본 설치는 브로커 클라이언트를 필수로 설치하지 않고, 각 extra는 해당 클라이언트만 추가하며, 두 extra를 선택하면 두 클라이언트를 모두 설치한다.
- [ ] 코어 및 선택한 브로커의 import가 선택하지 않은 브로커 클라이언트의 부재로 실패하지 않는다.
- [ ] RabbitMQ·Redis의 기존 기능 차이와 동작 제약을 확인하는 회귀 테스트가 포함된다.
- [ ] 한국어·영어 README, 브로커별 안내 및 샘플의 설치·사용 정보가 통합 결과와 일치한다.
- [ ] DefStream 배포 패키지에 두 브로커 구현체가 포함되며, 기존 어댑터 패키지나 프로젝트 없이 설치·실행할 수 있다.
- [ ] 기존 어댑터 패키지 배포 종료, 기존 프로젝트 삭제 예정 및 하위 호환성 미지원 정책이 문서화되어 있다.

## 7. 확정된 정책

1. **배포 방식:** DefStream 단일 패키지로 배포한다.
2. **기존 어댑터:** `DefStream-RabbitMQ`와 `DefStream-Redis` 패키지의 배포는 종료하며, 기존 프로젝트는 삭제 예정이다.
3. **호환성:** 하위 호환성은 지원하지 않는다.
4. **테스트 및 CI:** 두 브로커의 전체 테스트를 이관하고 CI에서 자동 실행한다. CI 작업을 브로커별로 분리할지는 구현 방식으로 정하되, 전체 테스트의 자동 실행 요구는 유지한다.
5. **공개 import 경로:** `DefStream.Broker.Implements.RabbitMQ` 및 `DefStream.Broker.Implements.Redis`를 유지한다.
6. **클라이언트 의존성:** extra를 통한 선택 설치를 유지한다. RabbitMQ extra는 `pika`, Redis extra는 `redis`를 설치하며, 기본 설치에는 두 클라이언트를 필수화하지 않는다.
