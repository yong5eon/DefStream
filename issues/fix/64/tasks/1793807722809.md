# 변경 후 회귀 검증과 문서 영향 확인

## 실행 환경과 결과

기존 프로젝트 가상환경의 Python 3.12.10을 사용했다. 저장소 루트에서 다음 명령을 실행해 테스트 14개가 모두 통과했다.

```shell
python -X utf8 -m unittest tests.test_protocol_contracts tests.test_worker_recovery.RecoveryTests.test_ack_timeout_and_exception_classification tests.test_worker_recovery.RecoveryTests.test_closed_idle_channel_is_detected_without_settlement
```

- 직접 상속, 비추상 클래스, 기존 인자를 통한 생성과 인스턴스 판별 검증이 통과했다.
- 기존 구조적 구현체 지원과 공통 Consumer·Redis Consumer의 비지원 검증을 유지했다.
- ACK 시간 초과와 연결 종료, 인증 실패, 복구 불가능 채널 오류 및 콜백 오류 분류 검증이 통과했다.
- 두 수정 Python 파일에 대한 Pylance 문법 검사에서 오류가 없었다.
- 변경 전후 Pylance 진단을 대조했다. 제품 파일에는 진단이 없고 테스트 파일에는 기존 `cb`, `seconds` 미사용 힌트 2개만 남았다. 새 타입 오류는 없다.

## 변경 범위 확인

제품 파일의 변경 전후 AST를 비교했다. `Recoverable` import와 직접 부모 추가를 제외하면 AST가 동일하므로 생성자와 `is_recoverable` 구현을 포함한 나머지 제품 코드가 유지됨을 확인했다.

테스트에서 import한 제품 모듈의 내용이 작업 트리 소스와 동일한 것도 확인했다. AST 비교는 저장소 밖 일회성 표준 입력 코드로 실행했으며 보존된 스크립트는 없다.

이슈 문서 12개의 상대 링크, 개인 절대 경로 노출과 줄 끝 공백을 검사해 통과했다. `git diff --check`도 통과했으며 전체 변경 목록이 해당 이슈 문서와 두 Python 파일로 한정됨을 확인했다.

## 문서 영향과 제한사항

공개 메서드·설정·사용법·오류 분류·운영 절차 변경이 없는 계약 선언 변경이다. 상세 매뉴얼과 한국어·영어 루트 README의 사용 안내를 갱신할 필요가 없어 수정하지 않았다. 변경 로그에도 사용자 대응이 필요 없음을 명시한다.

검증은 위의 관련 테스트와 정적 진단으로 한정했다. 전체 테스트, 다른 Python 버전과 실제 RabbitMQ 서버 통합 테스트는 실행하지 않았다. 이번 변경은 브로커 통신 구현을 바꾸지 않으므로 해당 검증으로 범위를 확대하지 않았다.

변경 전 실패는 [앞선 작업 기록](./1793807663435.md), 실제 선언 변경은 [구현 기록](../implements/1793807663436.md)에 기록했다.
