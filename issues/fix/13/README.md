# Worker 시작 배너와 샘플 로깅 순서

## 변경 요약

Worker 시작 배너를 로깅 설정 여부와 관계없이 먼저 확인할 수 있도록 Worker
샘플의 로깅 설정 시점을 `WorkerSetup` 훅으로 옮겼습니다. 시작 배너는 터미널에서
청록·파랑 계열로 강조하며, ASCII 아트의 모양과 문구는 유지합니다.

## 변경 내용

- [Worker 샘플](../../../samples/Worker/Sample.py)은 `configure_logging()`을
  실행 진입점에서 호출하는 대신 `SetupLogger` setup 훅에서 수행합니다.
  Worker 생성·작업 등록 시점의 로그는 아직 설정되지 않은 핸들러에 의해 출력되지
  않으며, 시작 배너가 샘플의 첫 화면 출력이 됩니다.
- [Startup](../../../src/Worker/Startup.py)은 stdout이 터미널이고 `NO_COLOR`
  환경 변수가 설정되지 않은 경우에만 로고에 색을 적용합니다. `Starting Worker`
  제목도 굵은 청록색으로 표시합니다. 파일·파이프 등으로 출력을 리다이렉트하거나
  `NO_COLOR`를 설정하면 ANSI 색상 코드를 출력하지 않습니다.
- `Worker.run()`의 로그와 배너 호출 순서는 변경하지 않았습니다. 따라서
  로깅 핸들러가 미리 설정된 애플리케이션에서는 `Starting Worker` 로그가 배너보다
  먼저 기록될 수 있습니다. 이 변경은 샘플의 로깅 설정 시점을 조정해 샘플 출력에서
  배너를 먼저 보이게 합니다.

## 호환성 및 검증 범위

시작 배너의 ASCII 문자와 구성 출력은 유지됩니다. 색상은 터미널 조건에서만
추가되며 `NO_COLOR`를 통해 끌 수 있습니다.

로고 색상 적용 후 ANSI 코드를 제거한 결과가 원본과 동일한지, 수정한 Python 소스의
문법이 유효한지 확인했습니다. Worker 시작 테스트는 환경에 `pika`가 없어 실행하지
못했으며, 샘플의 로깅 순서 변경은 별도 실행으로 검증하지 않았습니다.
