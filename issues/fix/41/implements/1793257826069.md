# Consumer 생명주기 로그를 DEBUG로 조정

[추가 INFO 축소 대상 조사](../tasks/1793257826068.md) 이후 사용자 요청에 따라 RabbitMQ 구현에 남은 INFO를 DEBUG로 낮췄습니다. Pika 로거 안내는 제외했습니다.

## 코드 변경

`src/Broker/Implements/RabbitMQ/Consumer.py`의 `self.logger.info(` 호출 7곳을 모두 `self.logger.debug(`로 변경했습니다. 메시지와 인자는 그대로입니다. 조사 기록의 "8곳"은 잘못 센 수치이며, 실제로는 아래 7곳입니다.

- `Consumer.subs()`: `Subscription applied`
- `Consumer.close()`: `RPC response channel closed`, `Consumption channel closed`
- `Consumer.run()`: `Starting consumption loop`, `Consumption loop ended`
- `Consumer.stop()`: `Consumption loop stop requested`, `Consumption loop stopped`

이 변경으로 `src/Broker/Implements/RabbitMQ/`에는 INFO 호출이 남지 않습니다. WARNING·ERROR 호출과 예외 전파는 바꾸지 않았습니다. Worker 시작·준비·종료 INFO는 `src/Worker/Worker.py`의 `DefStream.Worker` 로거에서 그대로 기록됩니다.

## 테스트·문서

- `tests/test_rabbitmq_logging.py`의 `test_consumer_receive_decode_handler_and_loop_error_ownership`
  - 구독·소비·중지 경로에서 INFO 이상 0건과 생명주기 DEBUG 메시지 5종을 확인합니다.
  - `close()`가 DEBUG 한 건(`Consumption channel closed`)만 남기는지 확인합니다.
- `docs/RabbitMQ.md`, `docs/RabbitMQ.en.md`: RabbitMQ 구현은 정상 동작을 INFO로 기록하지 않으며, Worker 생명주기는 `DefStream.Worker` INFO로 확인할 수 있다고 수정했습니다.

- `python -m unittest discover -s tests -p "test_rabbitmq*.py"`: 52개 통과, opt-in 통합 테스트 3개 건너뜀
- `python -m unittest discover -s tests -p "test_*logging*.py"`: 40개 통과
- `python -m unittest discover -s tests`: 267개 실행
  - 첫 실행: 실패 3, 오류 1, 건너뜀 15. 오류는 이후 실행에서 재현되지 않아 원인을 특정하지 못했습니다.
  - 이후 3회: 실패 3, 건너뜀 15. 변경 전과 같은 기존 `test_broker_packaging` 실패입니다.
