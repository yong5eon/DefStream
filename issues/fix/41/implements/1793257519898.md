# Connection 정상 연결·자원 작업 로그를 DEBUG로 조정

[사용자 제공 로그 분석](../tasks/1793257216492.md)에서 RabbitMQ INFO 216건이 모두 `Connection`의 연결 시도·성공·종료로 확인되어 해당 로그 경로를 수정했습니다.

## 코드 변경

`src/Broker/Implements/RabbitMQ/Connection.py`

- `Connection.connect()`: `Connecting to RabbitMQ: ...`를 INFO에서 DEBUG로 변경
- `Connection.observe()`: 성공 시 `... completed` 기록을 INFO에서 DEBUG로 변경. 실패 시 ERROR 기록 후 원래 예외를 다시 발생시키는 동작은 유지

```python
# 발췌, 독립 실행 불가
self.logger.debug('Connecting to RabbitMQ: host=%s port=%s vhost=%s', ...)
...
else:
  self.logger.debug(operation + ' completed', *context)
```

`observe()`는 연결·종료 외에 작업 큐 선언과 큐·Exchange·Stream 선언·삭제·바인딩·해제에도 쓰입니다. 이 성공 기록은 이미 DEBUG인 선언 옵션 기록과 같은 세부 단계이므로 함께 DEBUG로 통일했습니다. 연결만 INFO에서 제외하기 위한 레벨 매개변수나 분기는 추가하지 않았습니다. Consumer의 구독·소비 루프 INFO는 표본에 나타나지 않아 유지했습니다.

## 테스트·문서

- `tests/test_rabbitmq_logging.py`의 `test_connection_lifecycle_resources_confirm_and_request_delegation`: 기존 "INFO가 하나 이상" 기대를 "INFO 이상 0건"으로 바꾸고 DEBUG의 연결 시도·성공 기록을 확인합니다. 종료 기록은 DEBUG 한 건과 정확한 메시지를 확인합니다.
- `docs/RabbitMQ.md`, `docs/RabbitMQ.en.md`의 로깅 절: "연결·자원 변경은 INFO"를 Consumer 생명주기 INFO와 연결·자원 작업 성공 DEBUG로 구분해 수정했습니다.
