# RabbitMQ 로깅 요구사항

원문과 분석 근거는 [이슈 기록](./README.md)을 기준으로 합니다.

## 확정 범위

1. 원본 이슈의 제목·본문·유형·댓글을 확인하고 원문을 보존합니다.
2. 기존 변경을 보존하면서 `fix/41`로 전환합니다.
3. 현재 RabbitMQ 로그 발생 지점, 기존 테스트와 매뉴얼을 대조하여 INFO 과다의 원인 후보와 최소 변경 방향을 분석합니다.
4. 사용자가 제공한 INFO 로그에서 확인된 직접 원인인 `Connection`의 정상 연결 시도·성공·종료 INFO를 DEBUG로 낮춥니다.
5. 같은 성공 기록 경로(`Connection.observe()`)를 사용하는 큐·Exchange·Stream 선언·삭제·바인딩 성공 기록도 DEBUG로 통일합니다. 연결 전용 레벨 분기나 설정은 추가하지 않습니다.
6. 한국어·영어 RabbitMQ 매뉴얼의 로깅 정책을 변경된 동작에 맞춥니다.
7. 사용자 요청에 따라 RabbitMQ `Consumer`의 구독 적용·채널 종료·소비 루프 생명주기 INFO 7곳도 DEBUG로 낮춥니다. 이로써 RabbitMQ 구현은 정상 동작을 INFO로 기록하지 않습니다. Worker 생명주기 INFO는 `DefStream.Worker` 로거에 남습니다.

## 기존 계약 유지

- 원문의 목적은 RabbitMQ INFO 로그를 적절히 줄여 다른 로그의 가독성을 높이는 것입니다. 정확한 건수나 성능 목표는 원문에 없습니다.
- 정상 메시지·RPC·정산 추적은 이미 DEBUG이므로 변경하지 않습니다.
- 기존 WARNING·ERROR와 예외 전파, 민감정보 비노출, 로거 이름·상속·루트 전파 및 라이브러리 무설정 정책을 유지해야 합니다.
- 메시지 처리·정산·RPC·연결 API의 동작 변경, 연결 재사용·풀링, 다른 브로커나 Pika의 로그 정책 변경, 새 설정 API 추가는 범위에서 제외합니다. Pika는 원래 로그가 많은 라이브러리로 보고 안내도 추가하지 않습니다.

## 미확정 사항

- 다른 시간대의 로그 분포와 애플리케이션의 연결 생성 이유·사용 버전
- 병합 대상 브랜치

## 인수 기준

- 정상 연결·종료와 자원 작업 성공 시 RabbitMQ `Connection` 로거의 INFO 이상 기록이 0건입니다.
- DEBUG에서는 연결 시도·성공·종료 기록이 유지됩니다.
- Consumer의 구독·소비 루프·채널 종료 시 INFO 이상 기록이 0건이고 DEBUG에서 해당 기록이 유지됩니다.
- 연결·자원 작업 실패 시 ERROR 기록과 원래 예외 전파가 유지됩니다.
- 기존 RabbitMQ 테스트가 통과하고, 한국어·영어 매뉴얼이 변경된 레벨 정책과 일치합니다.
