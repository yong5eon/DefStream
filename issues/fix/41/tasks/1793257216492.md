# 사용자 제공 INFO 로그 집계와 분석 정정

## 수행과 결과

사용자가 제공한 읽기 전용 로그 첨부를 직접 분석했으며 원본을 저장소에 복사하지 않았습니다. 운영 주소·업무 식별자·셸 경로는 기록에 재수록하지 않습니다.

Python 표준 라이브러리로 전체 행을 읽어 시각·프로세스·스레드·레벨·로거·메시지 구조로 분류하고, 로거 이름과 메시지 종류별 건수를 집계했습니다. 처음 엄격한 형식 검사에서 마지막 셸 프롬프트 한 줄이 로그 형식이 아님을 확인한 후 해당 행을 명시적으로 제외했습니다. 나머지 336건은 모두 INFO 로그입니다.

- 제공 구간: 로그 시각 `06:58:48.860`부터 `06:58:53.112`까지 4.252초
- RabbitMQ: 216건, 전체의 64.3%, 모두 `DefStream.Broker.Implements.RabbitMQ.Connection`
- 연결 시도: 73건
- 연결 성공: 72건
- 연결 종료: 71건
- 나머지 애플리케이션 로그: 120건

이 표본에서는 Pika·Consumer·자원 선언 로그가 아니라 정상 연결의 세 단계 INFO가 직접적인 문제입니다. 메시지는 현재 `Connection.connect()`와 `Connection.observe()`의 기록과 일치합니다.

## 판단 정정

[최초 분석](./1793256929057.md)에서 제안한 연결 성공·종료 INFO 유지는 표본 기준 143건을 남기므로 충분하지 않습니다. 정상 연결 시도·성공·종료를 모두 DEBUG로 내리는 방향으로 제안을 변경하고 README·요구사항·계획·종합 결과를 갱신했습니다.

구간 시작·끝에 걸친 연결이 있으므로 시도·성공·종료 건수 차이를 실패나 누수로 단정하지 않습니다. 애플리케이션 호출부·설치 버전을 확인하지 않았으므로 작업당 연결 생성 원인이나 재사용 가능성도 미확정입니다. 연결 풀링·공유·성능 개선을 로깅 변경 범위에 추가하지 않습니다.
