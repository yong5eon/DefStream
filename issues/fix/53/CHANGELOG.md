# 브로커 구현체 설치 격리

## editable 갱신 안정성

개발용 설치 도중 일부 파일 연결 후 실패했을 때, 코어만 선택해도 구현체 코드가 남던 문제를 수정했습니다. 원인을 해결하고 원하는 목록으로 재실행하면 남은 파일을 정리하거나 필요한 연결을 완성합니다.

소스 교체·선택 변경 시 변경 없는 코어 파일까지 일시적으로 사라지던 문제를 수정했습니다. 변경 파일만 원자적으로 교체하며 `.DS_Store` 같은 미관리 파일이 있어도 선택 해제를 완료하고 해당 파일은 보존합니다. 전체 트리의 일괄 전환이나 실행 중 모듈의 자동 재로딩을 보장하지는 않습니다.

## 설치 방식

기본 `DefStream` 설치에는 공통 코드만 포함됩니다. RabbitMQ/Redis 구현체는 선택한 extra에 해당하는 별도 배포물로 설치되며 기존 import 경로를 유지합니다.

```shell
python -m pip install "DefStream[RabbitMQ]"
```

코어와 구현체는 동일 버전을 사용합니다. extra를 생략해 재설치해도 기존 구현체가 자동 제거되지는 않습니다.

개발 시 `pip install -e . --config-settings EXTRAS=RabbitMQ,Redis` 한 번으로 현재 로컬 소스의 코어와 선택 브로커를 갱신합니다. 환경변수나 코어 선행 설치는 필요하지 않습니다. 목록은 매번 교체되며 `pip install -e .`만 실행하면 기존 선택을 해제하고 코어만 남깁니다. 선택에서 빠진 외부 라이브러리는 자동 삭제하지 않습니다. 새 파일 추가·패키징 변경 후에는 원하는 목록으로 재실행하세요.

소스 코드를 수정하는 개발용 설치 절차와 sdist의 공통 소스 포함 범위는 [설치 매뉴얼](../../../docs/Packaging.md)을 참고하세요.

개발용 설치는 가상환경별로 공통 코드와 선택 구현체만 연결하여 IDE에서도 코드를 찾을 수 있습니다. 직접 링크를 만들 필요가 없습니다. Windows의 하드 링크 사용 시 소스와 가상환경은 같은 드라이브에 있어야 합니다.
