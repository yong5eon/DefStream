# 부분 갱신 실패 후 관리 파일 복구

DefPixel·DefEssential 후속 리뷰에서 재현된 부분 추가 후 실패 문제가 같은 helper를 사용하는 이 프로젝트에도 발생하여 함께 수정했다.

`scripts/editable_view.py`의 `refresh()`는 링크 변경 전에 기존 관리 파일과 새 요청 파일의 합집합을 `files.json`에 원자적으로 기록한다. 기록 실패 시 링크 변경을 시작하지 않는다. 모든 갱신이 성공하면 최종 요청 목록만 기록한다. JSON 기록의 기존 임시 파일·교체 로직은 `write_state()`로 공유했다.

이로써 링크 생성 도중 실패하거나 프로세스가 중단되어도 추가한 파일의 소유 정보가 남는다. 다음 갱신은 코어만 요청한 경우에도 빠른 반환으로 건너뛰지 않고 잔여 구현체를 제거한다. 같은 선택으로 재시도하면 누락 링크를 완성한다. 오류는 계속 전파하며 즉시 전체 롤백이나 전체 트리 원자성을 보장하지 않는다.

최초 설치·기존 코어 설치 각각에서 부분 실패 후 선택 해제·같은 선택 재시도, 소유 기록 실패 시 링크 미생성의 회귀 테스트를 추가했다. 한영 매뉴얼에 오류 원인 해결 후 재실행 안내를 반영했다. 일반 wheel과 공개 API는 변경하지 않았다. [검증 기록](../tasks/1793329241423.md).
