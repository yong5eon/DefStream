# 실패 후 bytecode 재사용과 검증 wheel 선택 수정

`.dev/scripts/editable_view.py`의 `refresh`는 임시 링크 생성 성공 후 최종 링크 교체 전에 `invalidate_bytecode`로 해당 `.pyc`를 정리한다. 후속 링크 실패로 함수가 종료되더라도 이미 교체한 파일에 이전 bytecode가 남지 않는다. 제거 파일의 캐시 정리도 같은 함수를 사용하며 변경 없는 링크·미관리 파일 보존·소유 정보·오류 전파 계약은 유지한다.

`.github/scripts/check_distributions.py`는 wheel 메타데이터에서 배포명별 로컬 경로를 수집한다. `local_requirements`는 코어를 extras 포함 파일 URI로, 선택 구현체를 직접 파일 경로로 지정하며 네 설치 조합과 순차 extra 추가에 함께 사용한다. 외부 의존성의 인덱스 사용은 유지한다. editable은 이미 로컬 소스를 직접 지정하므로 선택 계약을 변경하지 않았다.

실패 후 새 Python 프로세스의 실제 import와 pip의 경쟁 빌드 후보 선택을 검증하는 회귀 테스트를 추가하고 한영 매뉴얼을 갱신했다. 기존 Python 3.9 로그 테스트 수정은 보존했다. [검증 기록](../tasks/1793518878754.md).
