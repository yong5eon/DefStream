# 선택 링크 트리 기반 editable 구성

앞선 [조사](../tasks/1793297795667.md)의 정적 분석 제약을 해결하기 위해 사용자 승인을 받고 editable 연결 방식을 교체했다. 기존 `Broker` 부모 API와 선택 격리는 유지한다.

`setup.py`의 `EditableView`는 setuptools의 실제 출력·원본 매핑을 `editable-files.json`으로 저장하고 배포물별 보조 모듈과 `.pth`를 만든다. 임시 생성 파일처럼 지속적인 원본이 없는 출력은 명시적으로 거부한다. 코어와 구현체는 같은 전략을 사용한다.

`scripts/editable_view.py`는 해당 가상환경의 설치 메타데이터만 읽어 `site-packages/__editable_defstream_view/`를 관리한다. 코어와 설치된 구현체의 파일만 링크하고, `.pth`의 일반 경로 항목으로 노출한다. 같은 소스를 쓰는 다른 가상환경과 트리를 공유하지 않는다. 일반 wheel 구현체와 editable 코어의 조합도 설치 파일 기록을 이용한다. editable 구현체에는 이 방식의 editable 코어가 필요하다.

Python 시작 시 구성을 확인하고 변경이 있으면 이전 관리 파일과 해당 bytecode·빈 디렉터리를 정리하여 링크를 다시 만든다. 소스 파일이 원자적으로 교체된 경우도 링크를 갱신한다. 파일 잠금은 운영체제가 프로세스 종료 시 해제하므로 중단된 프로세스의 디렉터리 잠금이 남지 않는다. 잘못된 경로, 누락 원본, 버전 불일치와 잠금 오류는 명시적으로 드러낸다.

Windows에서는 파일 심볼릭 링크를 우선 사용하고 권한 부족일 때만 하드 링크를 사용한다. 하드 링크는 같은 볼륨이 필요하다. 파일 복사나 전체 소스 노출로 대체하지 않는다. 이 런타임 관리는 editable wheel에만 포함된다. `MANIFEST.in`으로 독립 sdist에도 보조 소스를 보존하며 빌드 의존성에 `wheel`을 명시했다.

`scripts/tests/test_editable_view.py`와 설치 검사에 소스 변경·원본 교체·제거·정적 경로 탐색·두 환경 격리를 반영하고 한국어·영어 매뉴얼을 갱신했다. [검증 결과](../tasks/1793299630939.md).
