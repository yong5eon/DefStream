# 요구사항

## 분석

`setup.py`는 모든 하위 패키지를 배포한다. RabbitMQ/Redis extra는 드라이버만 선택한다. 현재 패키징 테스트와 매뉴얼은 두 구현체가 코어에 포함되는 이전 계약을 명시하므로 이번 동작 변경에 맞춰 수정해야 한다.

같은 소스로 별도 구현체 배포물을 만들고 코어 extras가 이 배포물에 의존하게 한다. 과거 같은 이름의 별도 패키지를 사용한 환경은 안전한 전환 안내가 필요하다.

## 확정 요구사항

- 하나의 `src`와 `setup.py`를 유지하고 코어, RabbitMQ, Redis 배포물을 생성한다.
- 기본 설치에는 브로커 구현체가 없고, 각 extra는 해당 구현체만, 두 extra는 양쪽 구현체를 포함한다.
- 기존 import 경로와 코어 API를 유지하며 wheel 사이의 파일 소유권을 중복하지 않는다.
- 명시적인 빌드 대상을 검증하고 sdist에 대상을 보존하여 독립 재빌드가 가능하게 한다.
- 각 구현체 배포물은 같은 버전 코어와 자신의 외부 의존성에 의존한다.
- 사용자가 정션·심볼릭 링크를 직접 만들지 않고 한 번의 editable 설치로 코어와 선택 구현체를 현재 로컬 소스로 갱신한다. 새 파일 추가 후 재설치는 허용한다.
- editable은 단일 코어 배포물이 선택 구현체와 외부 의존성을 관리한다. `pip install -e . --config-settings EXTRAS=RabbitMQ,Redis`는 지정 목록으로 교체하며, `pip install -e .`은 기존 선택을 유지하지 않고 코어만 남긴다. 남아 있는 `DEF_BUILD_TARGET`은 editable 선택에 영향을 주지 않는다.
- editable에서도 선택한 구현체만 노출하고 기존 부모 API를 유지하며 정적 분석에서 import를 해석할 수 있어야 한다. 사용자 승인에 따라 가상환경별 선택 링크 트리를 자동 관리한다. 일반 wheel 설치에는 이 관리 동작을 넣지 않는다.
- 빌드·CI·배포 준비 및 한국어·영어 설치 문서를 함께 변경한다. 실제 배포는 수행하지 않는다.

## 인수 기준과 범위

- 깨끗한 환경의 기본/각 단일 extra/전체 extra 설치에서 파일, 배포 메타데이터, import를 검사한다.
- sdist 재빌드, 순차 빌드 혼입 방지, 동일 파일 중복, 추가 설치·제거, editable의 변경 반영을 검증한다.
- 기존 제품 테스트를 설치된 패키지에 대해 수행한다. 실제 브로커 연결 검증은 서비스 유무를 구분한다.
- 통합 배포 및 과거 별도 배포 버전은 제거 후 새 구성으로 설치하도록 안내한다.
- 일반 설치의 extras 생략에 의한 자동 제거는 요구하지 않는다.
- editable의 동일 버전 재설치·목록 교체·생략, 로컬 버전 변경, 새 파일 반영과 가상환경별 격리를 검증한다. 원격 소스나 외부 의존성의 강제 업데이트, 선택에서 빠진 외부 라이브러리 자동 삭제는 범위 밖이다.
- editable 백엔드는 pip를 중첩 호출하거나 대상 환경을 직접 설치·제거하지 않는다. 최초 전환 시 기존 별도 구현체 배포물은 명시적으로 제거해야 한다.
- 일반 배포의 빌드 대상 전달은 `DEF_BUILD_TARGET` 환경변수, 미지정 시 `core`로 정한다. 배포 이름은 `DefStream`, `DefStream-RabbitMQ`, `DefStream-Redis`로 유지한다.
