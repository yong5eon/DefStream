# EXTRAS 설치 검증과 개발 환경 전환

최소 Python 3.9에서 다음 명령으로 일반 배포와 새 editable 계약을 검사했다. 초기 Python 3.9 타입 별칭 import 실패는 수정 후 재검증했다.

```shell
python scripts/build_distributions.py --outdir dist/extras-editable --no-isolation
python scripts/check_distributions.py --dist-dir dist/extras-editable --editable
python -m unittest discover -s scripts/tests -t scripts -p 'test_*.py'
python -m twine check --strict dist/extras-editable/*
```

- 일반 배포의 3개 wheel·3개 sdist 빌드, 독립 sdist 재빌드, 네 설치 조합, 파일 소유권과 일반 구현체 추가·제거가 통과했다.
- editable에서 코어 → RabbitMQ → 양쪽 → Redis → 코어 → 양쪽을 같은 버전으로 재설치해 목록 교체·생략을 확인했다. 남아 있는 구현체 `DEF_BUILD_TARGET`이 editable 선택에 영향이 없음을 검사했다.
- 잘못된 이름·빈 쉼표 항목의 설치 실패 후 기존 선택이 유지됐다. 검증용 로컬 버전을 `0.2.0`에서 `9999.0.0`으로 바꿔 한 번의 설치로 갱신됐다. 제품 버전을 코드에 고정하지 않았다.
- 기존 소스 변경, 새 파일의 재설치 후 반영, 두 가상환경의 선택 격리, 런타임과 경로 기반 탐색, `pip check`가 통과했다.
- 단위 테스트 19개, 신규 패키징 코드 Pyright 오류 0개, 산출물 6개 twine strict 검사가 통과했다. 백엔드는 Pylance 구문 검사도 통과했으며 contextmanager 반환형을 `Generator`로 바꾼 뒤 해당 파일의 Pylance 진단은 0개다.
- 제품 패키징 테스트의 기존 일반 배포 전용 가정을 새 editable 계약과 구분했다. `python -m unittest discover -s tests -p test_broker_packaging.py`는 단일 editable과 기존 일반 wheel 환경에서 각각 4개 통과했고 해당 테스트의 Pyright 오류도 0개다.
- 한국어·영어 Packaging을 갱신하고 상대 링크·코드 펜스·개인 절대 경로를 검사했다.

사용자 승인 후 공용 개발 가상환경의 기존 DefStream 코어·별도 구현체 배포물을 제거하고 `python -m pip install -e . --config-settings EXTRAS=RabbitMQ,Redis`로 전환했다. Python 3.13의 실제 Git 개발 버전을 사용했고 기존 두 브로커 선택을 보존했다. 메타데이터에는 코어 배포물 하나만 있으며 두 import와 정적 경로 탐색, `pip check`가 통과했다.

이전 제품 전체 테스트 결과는 종합 기록에 보존한다. 이번 후속 변경에서는 패키징 회귀 검증을 수행했으며 RabbitMQ/Redis 실서버·원격 CI·게시 권한 검증은 여전히 미수행이다. 커밋·푸시·게시·이슈 종료는 하지 않았다.
