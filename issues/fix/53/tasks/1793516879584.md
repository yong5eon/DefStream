# 개발용 설치 코드 이동 검증

최소 지원 Python 3.9에서 저장소 루트 기준 `python -m unittest discover -s .dev/scripts/tests -t .dev/scripts -p 'test_*.py'`로 12개 테스트를 통과했다.

검증 버전 `0.2.0`을 환경변수로 지정하고 `python .github/scripts/build_distributions.py --outdir dist/dev-scripts --no-isolation`로 새 wheel/sdist를 빌드했다. `python .github/scripts/check_distributions.py --dist-dir dist/dev-scripts --editable`로 파일 소유권·독립 sdist 재빌드·네 설치 조합·설치 수명주기·editable 선택 갱신과 두 환경 격리를 통과했다.

Linux Python 3.9의 같은 discovery 명령으로 12개 테스트를 통과했고 helper·테스트·검사기의 타입 오류는 0개였다. 코드와 테스트의 이동 전후 동일성, Python 구문, CI 경로, sdist의 `.dev/scripts/editable_view.py` 포함, 일반 wheel 제품 파일 불변, 문서 링크와 `git diff --check`를 확인했다. 이전 검증에서 생성한 캐시와 비어 있는 루트 `scripts/`를 정리했다. 전체 제품 테스트와 원격 CI는 이번 단계에서 실행하지 않았다.

고객 설치 명령과 기능은 그대로이고 helper의 저장소 내부 위치만 바뀌므로 한영 매뉴얼과 고객용 변경 로그의 추가 수정은 필요하지 않다. 이전 워크플로 이동 기록은 당시 사실대로 보존한다. 커밋·푸시는 수행하지 않았다.
