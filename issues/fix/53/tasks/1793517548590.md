# Python 3.9 Inspector CI 실패 재현과 회귀 검증

[CI 실행](https://github.com/yong5eon/DefStream/actions/runs/41283849519)은 커밋 `953f633`에서 Python 3.9만 실패했고 3.10~3.14는 통과했다. 실패는 `test_response_write_timeout_through_run_is_logged_as_warning` 한 건이다. 앞선 Worker 복구 예외 출력은 성공한 테스트에서 발생한 로그이며 이번 실패 원인이 아니다.

로컬 Windows Python 3.9에서 `socket.timeout is TimeoutError`가 `False`이고 `socket.timeout.__name__`이 `timeout`임을 확인했다. 최초 테스트 명령은 검증 환경에 DefStream이 없어 import 단계에서 실패했다. 별도 Linux Python 3.9 컨테이너에 현재 코어 wheel을 설치하고 저장소 루트에서 `python -m unittest discover -s tests -p test_inspector_logging.py`로 실행하여 CI와 같은 대소문자 고정 기대값 실패를 재현했다.

수정 후 Linux Python 3.9와 3.13에서 같은 설치 wheel을 대상으로 `python -m unittest discover -s tests -p 'test_inspector*.py'`를 실행했다. 각 45개 중 41개 통과·4개 skip으로 성공했다. skip은 RabbitMQ·Redis 연결 테스트의 명시적 opt-in 환경변수를 설정하지 않은 데 따른 것이며 실제 브로커 연결 검증이나 전체 제품 테스트 통과를 의미하지 않는다.

제품 구현·로그 계약·설치 명령 변경이 없는 테스트 호환성 수정이므로 고객 매뉴얼과 변경 로그의 추가 수정은 불필요하다. 작업 브랜치 `fix/53`과 `git diff --check`를 확인했다. 수정 후 원격 CI와 커밋·푸시는 아직 수행하지 않았다.
