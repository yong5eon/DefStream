# 부분 추가 실패의 재현과 복구 검증

수정 전 세 프로젝트에서 구현체의 첫 링크를 만든 뒤 다음 링크를 실패시키고 코어로 갱신해도 구현체가 남는 것을 재현했다. 공통 테스트를 이 프로젝트에 먼저 추가했을 때 최초 설치·기존 코어 설치 및 선택 해제·재시도 조합의 4개 하위 사례가 모두 실패했다.

수정 후 Windows 최소 Python 3.9에서 `python -m unittest discover -s scripts/tests -t scripts -p "test_*.py"`로 24개 통과했다. Docker Linux Python 3.9에서 링크 테스트 12개도 통과했다. helper·테스트의 Pyright 검사와 Pylance 구문 검사를 통과했다.

별도 검증에서 일부 링크 생성 후 실패시키고 새 Python 프로세스로 코어 갱신을 실행했다. 잔여 구현체 디렉터리가 제거되고 `find_spec("Example.Selected")`가 `None`이며 최종 소유 기록이 코어만 포함하는 것을 세 프로젝트에서 확인했다.

이번 변경은 helper와 회귀 테스트에 한정하여 전체 배포 통합·전체 제품 테스트는 반복하지 않았다. 공유 개발 환경 재설치, 커밋·푸시·리뷰 해결 처리·원격 CI는 수행하지 않았다.
