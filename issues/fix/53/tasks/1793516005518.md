# 이동 경로와 빌드 연결 검증

최초 이동 검증에서 빌드 백엔드의 `build_distributions` import가 실패했다. 의존 관계를 확인하고 사용자 선택에 따라 백엔드·테스트를 같은 위치로 옮기고 pip의 백엔드 경로도 수정했다. 단순 경로 주입이나 코드 복제는 추가하지 않았다.

최소 Python 3.9에서 기존 위치의 런타임 helper 테스트 12개와 새 위치의 빌드·릴리즈 테스트 12개를 통과했다. 새 위치의 모든 Python 코드에 대한 타입 검사, YAML·CI 실행 경로·두 discovery 진입점·변경 감지와 구문 검사를 통과했다.

`python .github/scripts/build_distributions.py --outdir dist/workflow-scripts --no-isolation`로 코어·두 구현체의 wheel/sdist를 빌드하고 `python .github/scripts/check_distributions.py --dist-dir dist/workflow-scripts --editable`로 독립 sdist 재빌드·네 설치 조합·파일 소유권·설치 수명주기·editable 선택 교체·새 파일·두 환경 격리를 통과했다.

Linux Python 3.9에서도 두 discovery 진입점으로 각각 12개를 통과했다. sdist에 새 백엔드·빌드 스크립트와 런타임 helper가 있고 이전 경로는 없음을 확인했다. 이전 검증 산출물은 현 소스와 달라 단순 비교를 불변 근거로 사용하지 않았다. 검증용 소스 경로도 최초에는 패키지 매핑을 잘못 가정해 실패했으며, `setup.py`의 `PACKAGE_DIR`를 확인한 뒤 wheel의 모든 제품 파일이 현재 `src/` 원본과 일치함을 검증했다.

변경 감지는 `.github/scripts/*.py`로 새 Python 스크립트와 테스트를 포함하되 기존 JavaScript 자동화 변경을 새로 릴리즈 대상에 넣지 않도록 했다. Git pathspec이 하위 Python 테스트를 포함하는 것도 확인했다. 기존 제품 전체 테스트와 실제 원격 CI는 이번 단계에서 실행하지 않았다. 사용자가 지정한 Python 3.9 runner는 보존했다. 커밋·푸시는 수행하지 않았다.
