# editable의 정적 분석 호환성 후속 조사

사용자가 DefPixel의 editable 구현체는 실행되지만 Pylance에서 찾지 못한다고 보고했다. 같은 코어 strict·구현체 finder 설계를 사용하는 이 프로젝트도 정적 분석 호환성 검토 대상으로 남긴다. 이 프로젝트에서 동일한 IDE 진단을 직접 재현한 것은 아니다.

사용자는 설치 구조에서 해결하되 editable에서도 선택한 구현체만 노출해야 한다고 확인했다. 일반 wheel 격리만 유지하고 editable에 전체 소스를 노출하는 대안은 채택하지 않는다.

공유 부모는 일반 패키지이며 `Broker/__init__.py`는 `Connection`, `Configuration` 등 기존 API를 공개한다. 구현체를 별도 strict 트리로 바꾸는 것만으로 일반 부모 패키지 아래 경로가 합쳐지지는 않는다. PEP 420 namespace로 바꾸려면 기존 부모 API와의 호환성을 해결해야 한다. Pyright는 [pkgutil.extend_path의 동적 경로 확장을 지원하지 않는다고 설명한다](https://github.com/microsoft/pyright/issues/4280#issuecomment-1337816833).

기존 API와 선택 격리를 유지하는 간단한 설치 구조 수정안은 아직 확인하지 못했다. 코드·현재 가상환경·IDE 설정을 변경하지 않았다. 기존 런타임 검증 결과와 IDE 지원 여부를 구분하며, 설치 구조의 정적 분석 호환성은 미해결이다.
