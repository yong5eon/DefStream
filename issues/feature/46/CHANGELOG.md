# RabbitMQ Worker 소비 장애 복구

RabbitMQ 소비 채널·연결 장애 후 모든 큐의 소비가 멈춘 채 Worker가 작업 종료를 기다리던 상황을 개선했습니다. Worker가 같은 프로세스 안에서 내부 실행기와 브로커 연결·구독을 다시 구성합니다. 별도 supervisor는 필요하지 않습니다.

## 복구 설정

Worker 생성자의 `recovery_attempts` 기본값은 5회이고, `recovery_interval` 기본값은 60초입니다. 첫 복구는 즉시 수행하고 실패한 시도 사이에만 기다립니다. 전체 구독 복구에 성공하면 다음 장애의 횟수 한도를 초기화합니다. `recovery_attempts=0`이면 복구 없이 실패를 전파합니다.

ACK timeout, 연결 유실 등 복구 가능한 소비 장애를 처리하며 인증·권한 오류나 작업 코드 예외를 무조건 재시도하지 않습니다. 초기 연결·구독 오류는 기존처럼 전파하고, 정상 stop과 작업 완료 후 ACK 계약은 유지합니다.

## 작업과 종료 시 주의사항

- 전달한 Pool 객체는 유지하지만 내부 실행기는 교체됩니다. ProcessPool의 이전 작업 프로세스는 종료하며 해당 작업의 cleanup 완료는 보장하지 않습니다.
- ThreadPool의 이전 작업은 계속 실행되고 완료 후 스레드를 정리합니다. 종료되지 않는 작업은 자원을 점유하거나 프로세스 종료를 지연할 수 있습니다.
- 이전 작업의 콜백은 새 Consumer의 ACK·RPC 응답과 새 실행 상태에 영향을 주지 않습니다. 그러나 메시지 재전달에 의한 중복 실행과 이미 발생한 외부 부작용은 남으므로 멱등성을 보장해야 합니다.
- 복구 한도 초과·비복구 장애는 Worker 실패로 전파합니다. Worker 프로세스의 강제 종료를 보장하지 않습니다.
- DefStream ThreadPool·ProcessPool을 지원하며 사용자 지정 executor를 전달한 Pool의 복구는 지원하지 않습니다.
- ProcessPool의 종료 대기 중 작업 프로세스가 비정상 종료해도 종료가 무기한 멈추지 않도록 감지하며, 생존 프로세스 회수 후 미완료 작업을 실패 처리합니다.
- 소비 시작 직전 종료 요청 누락과, 복구 가능한 이전 연결 정리 오류 때문에 재연결을 시도하지 못하던 문제를 수정했습니다.
- 사용자 지정 executor의 소비 실패 종료는 비대기 shutdown을 요청합니다. 실행기 재생성은 여전히 지원하지 않으며 실행 중인 사용자 작업의 강제 종료를 보장하지 않습니다.

설정 예시와 지원 범위는 [RabbitMQ 매뉴얼](../../../docs/RabbitMQ.md#worker-소비-장애-복구)을 참고하세요.
