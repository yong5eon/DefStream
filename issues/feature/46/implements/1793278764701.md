# Linux spawn 공유 Event 수명 보존

[실패한 CI 작업](https://github.com/yong5eon/DefStream/actions/runs/40876968709/job/123458246790)의 최초 오류는 자식 프로세스 시작 시 `SemLock._rebuild`의 FileNotFoundError였습니다. 이후 ProcessPool 작업 실패·시간 초과가 연쇄 발생했습니다.

`src/Worker/Executor.py`의 프로세스별 `draining` Event는 start의 지역 변수로만 유지됐습니다. 부모의 Process.start는 시작 인자를 계속 보관하지 않으므로, 부모 참조가 사라지면 Linux의 이름 있는 세마포어가 자식의 복원 전에 제거될 수 있었습니다. `completed`와 같은 PID별 보관 방식으로 `draining`도 부모 Executor에 유지하도록 수정했습니다. 복구·cleanup 정책은 바꾸지 않았습니다.

부모가 만든 stopping 및 프로세스별 Event 5개의 약한 참조를 기록하고 GC 이후에도 모두 살아 있는지 확인하는 회귀 테스트를 추가했습니다. 이 테스트는 수정 전에 Windows에서도 실패했습니다. Linux의 실제 spawn 작업 실패도 수정 전 재현했습니다.

검증 결과는 [Linux spawn 수정 검증](../tasks/1793278764702.md)을 참고하세요. 기존 매뉴얼의 계약을 복원하는 내부 자원 수명 수정이므로 추가 사용법·설정 변경은 없습니다.
