# 후속 PR 리뷰의 프로세스 종료 및 Pool 경쟁 수정

[PR #49](https://github.com/yong5eon/DefStream/pull/49)의 후속 리뷰 4건을 수정했습니다.

- `src/Worker/Executor.py`: 프로세스마다 공유 `completed` Event를 생성합니다. wrapper가 결과·오류 전달을 마치면 Event를 설정하므로, 정상 종료 메시지를 monitor가 아직 읽지 않았다고 crash로 오인하지 않습니다. `os._exit(0)`처럼 wrapper를 건너뛴 종료는 완료 신호가 없어 감지됩니다. 비정상 exit code도 계속 오류로 처리합니다.
- 프로세스 종료 검사는 결과 큐 timeout 조건에서 분리하여 결과가 계속 도착해도 수행합니다. 비정상 실행 환경 실패는 stopping 설정 후 생존 프로세스를 회수하고 Future를 실패 처리합니다.
- 정상 종료 토큰을 받은 뒤 cleanup에서 발생한 오류는 별도로 식별합니다. graceful shutdown 중 이 오류를 받으면 기록하고 다른 작업 결과를 계속 수집하여 drain을 보존한 뒤 shutdown에서 실패를 전파합니다. setup·예상치 못한 실행 환경 오류는 기존 실패 경로를 유지합니다.
- `src/Worker/Pool.py`: 명시적 stop 요청을 별도 상태로 유지하고, restart가 이전 실행기를 폐기한 뒤 새 실행기를 설치하기 전에 확인합니다. stop 이후 Pool을 다시 열지 않습니다. 콜백과 교착할 수 있는 새 생명주기 잠금은 추가하지 않았습니다.

한·영 매뉴얼과 요구사항·계획을 갱신했습니다. [검증 기록](../tasks/1793278267423.md)에 실제 프로세스·제어된 큐·스레드 경계 검증 결과를 정리했습니다.
