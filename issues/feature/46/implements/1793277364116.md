# PR 리뷰의 종료·복구 경계 결함 수정

[PR #49](https://github.com/yong5eon/DefStream/pull/49)의 리뷰 6건을 확정 요구사항과 대조한 뒤 의도된 사용자 지정 executor 복구 미지원·ThreadPool 잔존 정책은 유지하고 다음을 수정했습니다.

- `src/Worker/Executor.py`: 프로세스가 정상 루프·cleanup을 완료하면 결과 큐로 PID를 보냅니다. monitor는 정상 알림 없이 종료되거나 비정상 exit code를 보인 프로세스를 graceful shutdown 중에도 감지합니다. 실행 환경 실패 시 생존 프로세스를 kill·join한 후 Future 실패 콜백을 실행합니다. abort와 실패 경로의 프로세스 회수는 같은 잠금과 메서드를 사용합니다.
- `src/Worker/Worker.py`: running 상태 공개 후 stopping을 다시 검사하여 소비 시작 직전 종료 요청을 놓치지 않습니다. 복구 시 Consumer·브로커 정리 경계의 복구 가능한 오류는 로그를 남기고 연결 재생성을 계속하며 복구 불가능한 오류는 전파합니다.
- `src/Broker/Implements/RabbitMQ/Connection.py`: close 전에 기존 연결·publisher 참조를 분리하여 close 실패 뒤 connect가 이전 연결을 재사용하지 않도록 했습니다.
- `src/Worker/Pool.py`: 사용자 지정 executor의 restart는 여전히 거부합니다. 장애 종료는 비대기 shutdown을 요청하여 원래 소비 오류 또는 restart 미지원 오류가 후속 정리 오류로 대체되지 않게 했습니다.

실제 프로세스 crash·정상 종료, 생존 프로세스 회수 후 콜백 순서, stop 경쟁, 정리 오류 분류, 이전 연결 폐기와 사용자 지정 executor 종료 테스트를 추가했습니다. 기존 즉시 반환 Mock 테스트는 실제 Pika BlockingChannel 소비 루프를 가짜 타이머 I/O로 구동해 대기 중 채널 종료를 감지하는 테스트로 바꿨습니다. Pika가 제공하지 않는 내부 상태의 타입 선언은 테스트용 하위 클래스에만 두었습니다.

한·영 RabbitMQ 매뉴얼과 요구사항·계획을 함께 갱신했습니다. 초기 대상 검증에서 테스트 정리의 Mock 가정 때문에 실패한 부분과 테스트 Mock의 소멸자 오류를 수정했습니다. 후속 기능 회귀 및 구버전 검증 결과는 작업 기록에 남깁니다.
