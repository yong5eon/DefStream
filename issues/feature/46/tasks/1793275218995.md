# 실행기 및 소비 복구 검증 중간 결과

사용자가 첫 복구는 즉시, 실패한 시도 사이만 1분 대기, 연결·전체 구독 복원 성공 시 다음 장애의 횟수 초기화를 확정했습니다. 이를 요구사항과 구현에 반영했습니다.

복구 테스트 17개는 통과했습니다. 실제 프로세스 종료·새 실행기 작업 처리, 실행 중 스레드가 남은 상태의 Worker 복구, 이전 작업 완료 후 monitor 정리, 이전 완료·실패·예약 콜백 격리, 미실행 작업 폐기, 기본 5회·60초와 지정 설정을 확인했습니다.

인접 회귀 검증은 단계별로 확대했습니다. 훅 검증에서 새 프로세스 실행 경로의 setup·cleanup 오류 전파 누락을 발견해, 실행 환경 오류를 결과 큐로 부모에 전달하도록 수정했습니다. 이후 복구·생명주기·시그널 테스트 27개가 통과했습니다. 최초 출력 인코딩 오류는 검증 프로세스의 `PYTHONIOENCODING=utf-8` 설정으로 해소했으며 제품 코드의 출력 계약은 바꾸지 않았습니다.

전체 `unittest discover -s tests` 실행은 296개 중 실패 3건·생략 15건이었습니다. 실패는 변경하지 않은 패키징 검증에서 설치/작업트리의 distribution 파일 목록이 wheel 경로와 일치하지 않는 환경 문제였습니다. 작업 디렉터리를 바꿔 재확인해도 설치 메타데이터 검증이 실패했습니다. 패키징 설정·설치 환경은 이번 범위에서 수정하지 않았습니다. 최종 회귀 결과는 후속 검증 기록에 남깁니다.

실제 RabbitMQ·Redis 서버를 사용하는 통합 검증은 활성화하지 않았습니다. Mock 기반 소비 검증을 실제 브로커 장애 복구 실측으로 표현하지 않습니다.
