# Worker 내부 복구 방식 확정

사용자가 최종 확정한 복구 방식을 [요구사항 명세](../REQUIREMENTS.md)에 반영했습니다. [이전 분석 기록](./1793272872217.md)에서 미확정이었던 실행 중 작업 처리와 재시도 기본값을 구체화했습니다.

- 외부 supervisor 없이 Worker가 기존 Pool 객체를 유지하고 내부 실행기를 교체한 뒤 브로커 연결·소비 채널·QoS·구독을 복원합니다.
- 복구 최대 횟수와 시도 간 고정 간격은 설정 가능하며 기본값은 5회·1분입니다.
- ProcessPool의 기존 작업 프로세스는 종료합니다. ThreadPool의 실행 중 작업은 강제 종료하지 않고, 이전 실행기에 종료를 요청한 뒤 작업 완료를 기다리지 않고 복구합니다.
- 이전 작업의 완료·실패 콜백은 새 실행기의 상태·정산·RPC 응답 경로와 격리합니다. 이전 스레드는 작업 완료 후 관련 자원과 함께 정리되어야 합니다.
- 작업이 끝나지 않는 스레드의 잔존, 재전달 작업과의 중복 실행·외부 부작용, 프로세스 종료 지연 가능성은 수용합니다. 모든 실행기에서 Worker 프로세스의 강제 종료를 보장하는 요구는 두지 않습니다.

이는 원문의 내부 채널 복구 제안과 후속 대화 중 검토했던 외부 supervisor 방식 대신 확정된 방향입니다. 원본 이슈 본문과 과거 기록은 보존했습니다. 이번 변경은 요구사항과 작업 기록 갱신이며 코드 구현·실행 테스트·실제 브로커 검증은 수행하지 않았습니다.
