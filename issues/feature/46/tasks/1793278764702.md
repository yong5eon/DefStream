# Linux spawn 공유 Event 수명 수정 검증

## 원인 및 재현

CI head와 로컬 HEAD가 같은 커밋임을 확인했습니다. Python 3.10 CI 최초 실패는 프로세스 자식의 공유 세마포어 복원 오류였습니다. Windows 전용 검증으로 이 운영체제 차이를 놓쳤습니다.

- 수정 전 Windows: 새 부모 Event 보존 테스트 실패
- 수정 전 WSL Debian·Python 3.13.5: 실제 ProcessPool 정상 종료 테스트에서 작업 프로세스 시작 실패

## 수정 후 검증

저장소 루트에서 기존 unittest 진입점을 사용했습니다. WSL에서는 기존 작업 소스와 Pika 등 순수 Python 의존성 경로를 재사용했고 자식 프로세스에도 PYTHONPATH를 전달했습니다.

- Linux·Python 3.13.5: 패키징 모듈을 제외한 기능 회귀 306개 실행, 290개 통과·16개 생략·실패 0건
- Linux·Python 3.13.5: `test_worker_recovery test_lifecycle_hooks test_process_signals` 40개 실행, 39개 통과·1개 생략
- Windows·Python 3.12.10: 같은 대상 40개 통과
- Windows·Python 3.10.11: 같은 대상 40개 통과

Linux 전체 검증의 첫 실행은 샘플 자식 프로세스에 import 경로가 전달되지 않아 샘플 2건이 실패했습니다. 테스트 실행 환경의 PYTHONPATH 전달을 보완한 뒤 전체 기능 회귀가 통과했으며 제품 코드로 우회하지 않았습니다.

패키징 환경 검증·실제 외부 브로커 장애 주입은 제외했습니다. 링크의 GitHub Actions 작업 자체를 재실행한 결과는 아니며 Linux·Python 3.10.22 조합을 직접 실행한 것도 아닙니다. 커밋·푸시·CI 재실행은 수행하지 않았습니다.
