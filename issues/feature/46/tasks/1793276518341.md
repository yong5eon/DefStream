# Python 3.9·3.10 복구 테스트 호환성 검증

Windows의 Python 3.9.13·3.10.11에서 기존 문자열 `patch('DefStream.Worker.Worker.startup')`를 실행해 사용자 CI 로그와 동일한 AttributeError를 재현했습니다. 실제 모듈에는 startup이 있지만 패키지에서 공개한 Worker 클래스에는 없음을 런타임으로 확인했습니다.

기존 구버전 인터프리터에는 pika가 없어 초기 테스트 import가 실패했습니다. 기존 3.12 의존성 경로 공유도 Redis 버전·async_timeout 요구 차이 때문에 사용할 수 없었습니다. 저장소 밖 임시 가상환경에 각 Python에 맞는 RabbitMQ·Redis 의존성을 설치하고 작업 소스를 연결한 후 아래 검증을 실행했습니다.

저장소 루트에서 `PYTHONIOENCODING=utf-8`, 테스트 모듈 경로 `tests`, RabbitMQ·Redis 통합 opt-in 비활성화 상태로 실행했습니다.

```shell
python -m unittest test_worker_recovery test_protocol_contracts test_worker test_lifecycle_hooks test_process_signals
```

- Python 3.9.13: 60개 통과
- Python 3.10.11: 60개 통과

사용자 CI의 Linux·Python 3.9.25 환경 자체를 실행한 결과는 아니며 전체 299개 테스트와 실제 브로커 장애 주입은 다시 실행하지 않았습니다.
