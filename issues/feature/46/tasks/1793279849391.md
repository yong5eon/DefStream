# ThreadPool 중복 오류 로그 수정 검증

새 회귀 테스트는 폐기 상태에서 하나의 실행 단위가 먼저 실패하고 다른 실행 단위가 나중에 동일 예외 객체로 실패하도록 순서를 제어했습니다. 마지막 실행 단위는 5번째 큐 폴링까지 남도록 했습니다.

- 수정 전: 기대 오류 로그 2건 대신 5건으로 실패
- 수정 후: 각 실행 단위의 오류 로그가 한 번씩 총 2건이며, 늦게 발생한 오류도 기록
- Windows Python 3.12.10: `python -m unittest test_worker_recovery test_lifecycle_hooks test_process_signals` 41개 통과
- WSL Debian Python 3.13.5: 같은 대상 41개 실행, 40개 통과·1개 생략

저장소 루트에서 기존 테스트 경로와 UTF-8 출력을 사용했습니다. Linux에서는 기존 순수 Python 의존성 경로를 재사용했습니다. 실제 외부 브로커 장애 주입·전체 기능 회귀·GitHub CI 재실행은 이번 작은 변경 후 다시 수행하지 않았습니다. 커밋·푸시 및 리뷰 스레드 상태 변경도 하지 않았습니다.
