## 이슈 원문

## 해결하려는 문제

Worker에서 제공하는 `emit`과 `request`는 현재 브로커 호출이 실패하면 즉시 예외를 전파한다. 일시적인 실패에 대응하려면 호출자가 각 호출부에서 재시도 로직을 직접 작성해야 한다.

## 제안하는 해결 방법

`src/Worker/Message.py`의 `emit`과 `request`에 재시도 횟수와 시도 간 대기 간격을 지정하는 선택 인자를 추가한다. 브로커 구현체가 아닌 Worker 함수 계층에서 처리한다.

### 옵션과 기본값

| 옵션 | 기본값 | 의미 |
| --- | --- | --- |
| 최대 재시도 횟수 | `None` | 최초 호출을 제외하고 추가로 시도할 최대 횟수 |
| 재시도 간격 | `1`초 | 실패 후 다음 시도 전 대기 시간 |

인자명은 구현 시 기존 API 명명 관례에 맞춰 확정한다.

### 동작

- 재시도 횟수가 `None`이면 기존과 동일하게 한 번만 호출하고, 실패 시 대기 없이 해당 예외를 즉시 전파한다.
- 재시도 횟수가 `0`이면 추가 시도 없이 최초 호출 결과만 반환하거나 예외를 전파한다.
- 재시도 횟수가 `N`이면 최초 호출 이후 최대 `N`번 추가로 시도한다. 예를 들어 `3`이면 최초 호출을 포함하여 최대 `4`번 호출한다.
- 최초 호출은 즉시 실행하며, 실패 후 다음 시도가 남아 있을 때만 지정한 간격만큼 대기한다.
- 도중에 성공하면 기존 반환값을 즉시 반환하고 추가로 시도하지 않는다.
- 모든 시도가 실패하면 마지막 시도에서 발생한 예외를 다른 예외로 감싸거나 대체하지 않고 그대로 `raise`한다. 마지막 실패 뒤에는 대기하지 않는다.
- `emit`과 `request`에 동일한 재시도 정책을 적용한다. 기존 인자와 브로커 호출의 반환값·예외 계약은 유지한다.
- `request`의 기존 `timeout`은 각 브로커 요청 호출에 그대로 전달한다. 전체 재시도 과정의 총 제한 시간으로 바꾸지 않는다.

### 구현 범위

- Worker의 `emit`·`request`에서 브로커 호출 실패에 대한 재시도를 제공한다.
- 브로커 구현체 및 브로커 인터페이스에 재시도 옵션이나 내부 재시도 기능을 추가하지 않는다.
- Worker의 기존 입력 검증과 지원 기능 확인은 유지하고, 이를 브로커 호출 재시도 대상으로 확대하지 않는다.
- 재시도 미설정 시 기존 동작을 유지한다.

## 고려한 대안

- 브로커별 구현체에 재시도를 구현하는 대신, 호출자가 사용하는 Worker 함수 계층에서 공통으로 제공한다.

## 인수 기준

- [ ] `emit`과 `request` 모두 최대 재시도 횟수와 대기 간격을 지정할 수 있으며, 기본값은 각각 `None`과 `1`초이다.
- [ ] `None` 또는 `0`이면 한 번만 호출하고 실패 예외를 즉시 전파한다.
- [ ] 재시도 횟수 `3`에서 계속 실패하면 총 `4`회 호출하고 대기는 `3`회만 수행한다.
- [ ] 도중에 성공하면 반환값을 그대로 반환하며 남은 시도와 대기를 수행하지 않는다.
- [ ] 지정한 간격과 기본 간격이 실제 재시도 대기에 적용된다.
- [ ] 최종 실패 시 마지막 예외 객체와 타입을 그대로 전파하며, 별도 예외로 변환하지 않는다.
- [ ] 기존 `priority` 전달과 `request`의 `timeout` 전달을 유지한다.
- [ ] 브로커 구현체에 재시도 기능을 추가하지 않고 두 Worker 함수에서 검증한다.

## 추가 정보

기존 동작을 바꾸는 것이 아니라 선택적으로 사용할 수 있는 공개 기능을 추가하므로 `feature`로 분류한다.

재시도는 중복 전송이나 중복 실행 방지를 보장하지 않는다. 전송 이후 응답 대기 중 실패하는 등의 경우에는 이미 처리된 요청이 다시 전송될 수 있음을 사용 문서에 안내한다. 이 이슈에서 별도의 중복 방지 기능은 추가하지 않는다.
