# 연결 타이머 단위 검증과 사용 안내 반영

- VS Code에서 선택된 개발 가상환경의 Python 3.12.10과 Pika 1.4.4를 확인했다. editable import 내용이 현재 저장소 소스와 일치함도 확인했다.
- 기본 터미널 Python 3.14의 기존 editable 설치는 다른 드라이브 간 링크 생성 실패로 모듈을 불러오지 못했다. 해당 환경이나 설치를 수정하지 않고 선택된 가상환경에서 검증했다.
- 선택된 환경에서도 기본 콘솔 출력이 cp949여서 기존 Worker 배너 출력이 실패했다. 파일 인코딩을 변경하지 않고 검증 프로세스의 `PYTHONIOENCODING=utf-8`을 지정했다.
- 구현 전 관련 4개 모듈의 기준선 35개 테스트가 통과했다. 구현 후 계획의 5개 모듈을 한 번에 실행하여 48개 중 44개가 통과하고 opt-in 통합 테스트 4개는 건너뛰었다.
- 변경 Python 파일 5개의 Pylance 진단에서 타입 오류는 없었다. 테스트용 콜백의 미사용 인자에 대한 정보성 진단만 있었으며, 신규 테스트 파일의 구문 검사도 통과했다.
- 로컬 RabbitMQ 테스트 포트의 연결 확인이 시간 초과됐다. 실제 브로커의 유휴 실행·재등록·예외 전파까지 통과한 것으로 보고하지 않는다.
- 한국어·영어 RabbitMQ 매뉴얼에 등록·취소·제한된 반복 실행 예제와 기반 API의 이벤트 처리·소유 스레드 제약을 반영했다. 매뉴얼 진입점의 기존 RabbitMQ 항목도 함께 갱신했다.
- 상세 사용법은 기존 RabbitMQ 매뉴얼에 집중하며 프로젝트 소개·최소 Worker 예제를 바꾸지 않으므로 루트 README 요약은 변경하지 않는다.
- 사용한 단위·회귀 명령은 저장소 루트의 `python -m unittest tests.test_protocol_contracts tests.rabbitmq.test_rabbitmq_timers tests.rabbitmq.test_rabbitmq_broker_methods tests.rabbitmq.test_rabbitmq_logging tests.rabbitmq.test_rabbitmq_timeouts -q`이다. 실제 호출 시 선택된 개발 가상환경의 Python을 사용했다.
