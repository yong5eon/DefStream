# 타이머 및 Consumer 계약 요구사항 분석

- 이슈 원문과 대화에서 확정한 내용을 Connection·Consumer·RabbitMQ·Redis 구현, Worker 결과 처리·중단, Inspector Ping의 실제 호출 흐름에 대조했다.
- `SetTimer`, `Timer`, `TimerCallback`과 연결 객체의 선택적 타이머 기능을 명세했다. 외부 스레드 타이머나 Redis 타이머 구현은 범위에 추가하지 않았다.
- Consumer는 ABC를 유지하는 것으로 사용자 확인을 받았다. `complete`, `fail`, `call` 제거와 `close`의 `@abstractmethod` 선언을 명세했다.
- Redis Consumer의 close는 중단·닫힘 상태 설정만, RabbitMQ Consumer의 close는 소비자 측 채널 정리만 수행하며 연결 자체는 닫지 않음을 확인했다.
- Redis가 상속하는 기본 ACK와 Worker·Ping의 직접 호출 의존성을 확인하여 회귀 검증 범위에 포함했다.
- 연결 단위 타이머와 소비 종료 정리의 관계, 시간 계산 시작점·스레드 계약·등록 시그니처 등 미확정 사항을 [요구사항](../REQUIREMENTS.md)에 분리했다. 이를 확정한 뒤 구현 계획을 작성해야 한다.
- 적용 지침: `instructions/`의 범위를 확인했으며, 요구사항 문서는 공통 Markdown·이슈 기록 지침을 적용했다. `instructions/README.instructions.md`는 루트 README 전용이고 `instructions/DOCS.instructions.md`는 향후 제품 매뉴얼 갱신에 적용한다.
- 제품 코드·테스트·매뉴얼은 변경하지 않았다. 제품 테스트는 실행하지 않았다. 문서 검증 결과는 아래에 기록한다.

## 문서 검증 결과

- PowerShell 검사로 이슈 디렉터리의 Markdown 문서 4개에 대한 최상위 제목, 상대 링크 대상 존재, 로컬 절대 경로 미포함을 확인했다.
- `gh issue view 62 -R yong5eon/DefStream --json body`로 원문을 다시 조회하여 README의 원문 구역과 줄바꿈·끝 공백을 정규화한 내용이 일치함을 확인했다.
- 최초 절대 경로 검사식이 HTTPS URL을 드라이브 경로로 오인하여 실패했다. 검사식을 수정한 후 전체 문서 검사를 통과했으며 문서 내용의 문제는 아니었다.
- 저장소 루트에서 `git diff --check`가 통과했다. `git status --short`에서 변경이 이 이슈의 문서에만 있음을 확인했으며 실제 브랜치는 `feature/62`이다.
