# Connection 타이머 구현 계획 작성

- 확정 요구사항과 현재 연결 계약·공개 import·RabbitMQ의 `connected`·종료 처리·기존 테스트 및 매뉴얼을 대조하여 [작업 계획](../PLAN.md)을 작성했다.
- 공통 계약과 공개 import 추가, 기존 RabbitMQ 연결 모듈 안의 등록·취소 핸들 구현, 직접 관련 검증, 한국어·영어 사용 안내, 결과 기록 순서와 각 완료 조건을 명시했다.
- 등록 당시 Pika 연결과 핸들만 보관하여 직접 취소 API에 전달하는 방향을 계획했다. 별도 상태 관리·타이머 목록·자동 정리·동기화·콜백 래퍼는 추가하지 않는다.
- 기존 unittest·Mock, `RABBITMQ_TESTS` opt-in, `rabbitmq_test_port`를 재사용하는 검증을 계획했다. 신규 테스트 모듈·클래스는 아직 없는 예정 대상으로 명시했으며, 실제 RabbitMQ 검증을 단위 테스트로 대체 완료하지 않도록 구분했다.
- 적용 지침은 `instructions/CODE.instructions.md`, `instructions/DOCS.instructions.md`, `instructions/README.instructions.md`의 해당 범위와 공통 Python·Markdown 지침이다. 향후 Python 코드 내 설명·진단은 프로젝트의 영어 정책을 적용하고, 계획·진행 설명은 한국어로 작성한다.
- Consumer 등 제외 범위와 별도 이슈 #63·#64를 변경하지 않는다. 계획 작성 전 실제 브랜치는 `feature/62`였고 작업 트리는 깨끗했다.
- 이번에는 계획과 이슈 기록만 작성했으며 제품 코드·테스트·매뉴얼은 변경하지 않았다. 제품 테스트도 실행하지 않았다. 다음 단계는 계획의 공통 계약·공개 import 구현이다.

## 검증

- PowerShell 검사로 이슈 문서 9개의 제목·코드 펜스·상대 링크 대상 파일·로컬 절대 경로 미포함을 확인했다.
- 계획에 공개 계약·등록·취소 위임·기존 테스트 실행 명령·실제 RabbitMQ opt-in·진행 상태가 포함됐음을 확인했다.
- 저장소 루트의 `git diff --check`가 통과했으며 `git status --short`에서 변경이 이 이슈의 문서 5개에만 있음을 확인했다.
