# 작업 기록

## 2026-10-19: 기본 우선순위 위치 통합

- 사용자 의도에 맞춰 기본 우선순위를 작업의 `Subscription.priority`로 옮기고 `Run.priority`를 제거했다.
- 구독 객체·매핑의 기본값 읽기와 상속 검증을 수정하고 요구사항·사용 예제·구현 기록을 갱신했다.
- 전체 코어 테스트 137개 중 133개 통과, 선택적 테스트 4개 건너뜀을 확인했다.
- Redis 회귀 테스트 14개 중 10개 통과, 선택적 통합 테스트 4개 건너뜀을 확인했다.
- RabbitMQ 실서버를 포함한 어댑터 테스트 38개가 모두 통과했다.

## 2026-10-19: 우선순위 요구사항 정책 확정

- 사용자 결정에 따라 기본·최대 우선순위를 작업 정의에 두도록 명세를 갱신했다.
- 큐 최대값은 작업의 브로커별 구독 설정을 사용하고 RabbitMQ `Subscription`을 활용하도록 정리했다.
- 호출별 우선순위 생략 시 작업 기본값 사용, 자식 작업의 설정 해제 금지를 반영했다.
- 작업과 브로커를 기준으로 최대값을 검증하고, 서버 조회나 선언 이력 캐시를 추가하지 않도록 정리했다.
- Redis 제외와 RabbitMQ classic 큐 사용 전제를 유지했다.
- 두 프로젝트 명세의 정책 및 인수 기준을 대조했다. 문서만 변경했으며 구현이나 실행 테스트는 수행하지 않았다.

관련 문서: [요구사항 명세](./REQUIREMENTS.md)

## 2026-10-19: 우선순위 일부 생략 정책 확정

- 작업 기본 우선순위만 정의하면 브로커 허용 상한을 큐 최대값으로 사용하도록 변경했다. RabbitMQ에서는 `255`를 사용한다.
- 최대 우선순위만 정의하면 기본값은 `None`이고, 호출별 값도 없으면 메시지 우선순위 속성을 생략하도록 명시했다.
- 자식 작업의 상속 설정 해제 금지는 유지했다.
- 선언과 전송 검증에서 같은 유효 최대값을 사용하도록 정책과 인수 기준을 갱신했다. 문서만 변경했으며 실행 테스트는 수행하지 않았다.

## 2026-10-19: 호출에서만 우선순위를 지정하는 정책 확정

- 작업의 기본·최대값 없이 호출에서만 우선순위를 지정하면 브로커 허용 범위만 검증하여 발행하도록 확정했다.
- 우선순위 큐 사전 선언 및 실제 큐 최대값 준수는 호출자 책임으로 명시했다.
- 요구사항과 인수 기준을 갱신했다. 문서만 변경했으며 실행 테스트는 수행하지 않았다.

## 2026-10-19: Docker RabbitMQ 실서버 검증

- 제공된 Docker 환경을 기본 계정과 `/` vhost로 실행했다.
- 코어 메시지·우선순위 테스트 18개 중 16개가 통과했고 Redis 전용 통합 테스트 2개는 건너뛰었다.
- RabbitMQ 어댑터 전체 35개 테스트가 모두 통과하여 기존 실서버 검증 제한을 해소했다.
- 테스트 종료 후 생성된 큐가 남아 있지 않음을 확인했다.
