# Subscription timeout 구현 계획

작업 대상과 병합 대상은 [이슈 기록](./README.md), 범위와 인수 기준은 [요구사항 명세](./REQUIREMENTS.md)를 따릅니다.

## 구현 기준

- `Subscription`의 마지막 선택 필드에 `timeout: Optional[Union[int, timedelta]] = None`을 추가하여 기존 위치 인자를 유지합니다.
- `None`, 밀리초 단위의 양수 `int` 또는 정수 밀리초로 정확히 표현 가능한 양수 `timedelta`를 허용합니다. `bool` 및 다른 타입은 `TypeError`, 0·음수·밀리초 미만 정밀도는 `ValueError`로 처리합니다.
- 생성 시 `timedelta`의 정수 나눗셈으로 값을 정수 밀리초로 통일하고 `declare()`는 해당 값을 전달합니다. 사용자 확인에 따른 정수 입력 지원을 반영한 계획이며 브로커의 운영 권장 최소시간은 추가하지 않습니다.
- `Connection.declare()`에서 작업 큐에만 `x-consumer-timeout`을 전달합니다. 오류 큐·소비 등록·ACK·RPC·운영 환경은 변경하지 않습니다.

## 수행 순서와 진행 상태

1. [완료] 현재 구독·큐 선언 및 기존 테스트의 기준 동작 확인
2. [완료] timeout 테스트 추가와 구독 설정·선언 구현 (R-01~R-09)
3. [완료] 한국어·영어 RabbitMQ 매뉴얼에 설정 예시·선언 방법·검증 계약 반영 (R-10)
4. [완료] 대상 회귀 테스트·타입 진단·문서 링크 검증, 실제 결과에 따른 종합 기록과 변경 로그 작성

실제 검증 결과와 생략 범위는 [최신 검증 기록](./tasks/1793272077066.md), 구현 결과는 [구현 종합](./IMPLEMENTS.md)에 정리했습니다.

## 검증 계획

- AC-01~AC-04: 객체·Mapping·Worker 선언 경로, 24시간 및 정밀도 경계값, 생략·`None`, 기존 위치 인자, DLQ·우선순위 병합, I/O 전 오류를 Mock 기반 테스트로 검증합니다.
- AC-05~AC-07: 소비 등록에서 선언·timeout 소비 인자가 없음을 검증하고, 기존 구독·ACK·실패 정책·prefetch·RPC 및 선언 오류 전파 테스트를 함께 실행합니다.
- AC-08: 한국어·영어 예시와 입력 계약의 일치 및 상대 링크를 확인합니다.
- 기존 `unittest`와 Pylance 파일 진단을 사용합니다. 실제 브로커 ACK 만료 대기·기존 큐 변경·운영 설정 확인은 실행하지 않습니다.
- 브로커 데이터나 스키마를 변경하지 않으므로 운영 마이그레이션·복구 절차는 필요하지 않습니다.
