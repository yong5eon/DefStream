# timeout 구현 검증 결과

## 실행 환경과 명령

Python 3.12.10의 기존 작업공간 환경을 사용했습니다. 설치된 `DefStream` 경로가 현재 저장소의 `src`로 연결된 junction임을 확인하여 변경 소스를 검증했습니다. 의존성 설치나 환경 수정은 하지 않았습니다.

저장소 루트에서 `tests`를 Python import 경로에 추가하고 `PYTHONIOENCODING=utf-8`로 다음 명령을 실행했습니다.

```shell
python -m unittest test_rabbitmq_timeouts test_rabbitmq_worker test_rabbitmq_priorities test_rabbitmq_rpc test_task_messages test_worker test_rabbitmq_logging
```

최종 결과는 92개 중 88개 통과, 4개 생략, 실패·오류 없음이며 종료 코드는 0입니다. 전체 테스트 스위트나 실제 브로커 검증을 수행한 결과는 아닙니다.

## 인수 기준 확인

| 기준 | 실제 확인 결과 |
| --- | --- |
| AC-01 | 객체·Mapping 및 Worker `declare()` 경로에서 24시간이 정수 `86400000`으로 전달됨 |
| AC-02 | 생략·`None`에서 인자 미전달, 기존 위치 인자 순서 유지 |
| AC-03 | DLQ·우선순위와 timeout 인자 병합, 오류 큐에는 timeout 미전달 |
| AC-04 | 1밀리초·큰 기간의 정확한 변환, 잘못된 타입·0·음수·밀리초 미만 정밀도는 I/O 전 오류 |
| AC-05 | 소비 등록 시 큐 미선언, timeout 소비 인자 미전달 및 수동 ACK 유지 |
| AC-06 | 기존 Worker·소비·실패 정책·prefetch·RPC 회귀 테스트 통과, RPC 응답 timeout 독립성 확인 |
| AC-07 | 선언 오류 전파 및 큐 자동 삭제 없음 확인 |
| AC-08 | 한국어·영어 매뉴얼의 Worker 예제와 timeout 예제를 브로커 I/O 없이 실행하고 24시간 설정 확인 |

Pylance `textDocument/diagnostic`에서 변경한 `Subscription.py`, `Connection.py`, `test_rabbitmq_timeouts.py` 모두 진단이 없었습니다. 문서 상대 링크·절대 경로 노출 및 `git diff --check`도 확인했습니다.

## 진행 중 확인한 제한

- 구현 전 새 테스트는 기존 API에 `timeout`이 없어 실패했고, 구현 후 새 테스트 9개가 모두 통과했습니다.
- 첫 회귀 실행은 기존 시작 배너의 Windows cp949 출력 인코딩 오류로 실패했습니다. 제품 코드는 변경하지 않고 UTF-8 출력으로 동일 테스트를 다시 실행하여 해결했습니다.
- 테스트 출력을 요약하려던 표준입력 기반 실행은 Windows ProcessPool의 spawn이 표준입력 진입점을 재실행할 수 없어 중단했습니다. 해당 실행 프로세스를 종료하고 표준 `python -m unittest` 진입점으로 최종 검증했습니다.
- 기존 큐 변경·ACK 만료 대기·브로커 운영 환경 검증은 사용자 지정 범위 밖이므로 수행하지 않았습니다.
