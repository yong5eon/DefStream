# consumer timeout 요구사항 분석·명세 결과

[이슈 원문](./README.md)과 현재 코드의 계약을 바탕으로 [요구사항 명세](./REQUIREMENTS.md)를 작성했습니다. 큐 선언에서만 ACK 대기 한도를 설정하고, 미지정 동작·완료 후 ACK·실패 정책·prefetch를 유지하는 범위를 정리했습니다.

사용자의 후속 확인에 따라 범위를 `Subscription`에 지정한 timeout을 `declare()`에서 큐 인자로 전달하는 기능으로 한정했습니다. 기존 큐 변경·반영 확인과 운영 조치는 범위 밖이며, 추가 사용자 결정 사항은 없습니다. 정수 입력 지원 요청을 반영하여 `timeout`은 `Optional[Union[int, timedelta]]`로 받고 생성 시 정수 밀리초로 정규화합니다.

[작업 계획](./PLAN.md)을 작성하고 구현 후 관련 테스트를 검증했습니다. 92개 중 88개 통과·4개 생략이며, 변경 Python 파일 3개의 Pylance 진단은 없습니다. 한국어·영어 매뉴얼의 Worker·timeout 예제는 브로커 I/O 없이 실행하여 확인했습니다. 구현 설명은 [구현 종합](./IMPLEMENTS.md), 상세 결과와 실행 제한은 [검증 기록](./tasks/1793271819682.md)을 참고하세요.

실제 RabbitMQ의 ACK 만료 대기·기존 큐 변경·운영 환경 검증은 수행하지 않았습니다. 커밋·푸시·PR 생성은 하지 않았습니다.
