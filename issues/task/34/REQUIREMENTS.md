# DefStream #34 요구사항 명세서

## 목적과 근거

- 근거 이슈: [#34](https://github.com/yong5eon/DefStream/issues/34), [이슈 기록](./README.md)
- 작업 브랜치: `task/34`
- 대상: [CI 워크플로](../../../.github/workflows/ci.yml) 및 DefStream에 적용할 프로젝트별 세부 지침

공통 지침의 문서 역할 구분에 맞게 CI가 릴리즈 변경 로그를 찾는 파일명을 변경하고, DefStream에 필요한 프로젝트별 세부 지침을 추가한다.

## 범위

### 포함

- CI에서 릴리즈용 이슈 변경 로그의 경로를 `issues/{branch}/CHANGELOG.md`로 변경한다.
- DefStream의 루트 README와 상세 매뉴얼 각각에 대한 프로젝트별 세부 지침을 추가한다.

### 제외

- 릴리즈 조건, 버전 산정, 배포 절차 및 변경 로그 검증 정책 변경
- 이슈 원문·메타데이터를 담는 `README.md`를 변경 로그로 계속 사용하는 것
- DefEssential 또는 공통 작업공간의 파일 변경
- 이 이슈에서 지정하지 않은 프로젝트 동작·공개 API 변경

## 요구사항

### CI-01. 변경 로그 경로

- CI는 병합된 작업 브랜치의 `issues/{branch}/CHANGELOG.md`를 릴리즈 변경 로그로 읽어야 한다.
- 파일 누락 또는 비어 있는 변경 로그는 기존과 같이 명시적으로 실패해야 한다.
- 읽은 변경 로그의 내용은 기존 릴리즈 노트 생성·보관 동작에 전달되어야 한다.
- 릴리즈 이벤트 조건과 배포 동작은 변경하지 않는다.

### INS-01. 루트 README 지침

- `instructions/README.instructions.md`에 `README.md`, `README.en.md`, `README.setup.md`의 작성·수정 규칙을 정의한다.
- `README.md`는 한국어 프로젝트 소개와 핵심 사용 안내, `README.en.md`는 이에 대응하는 영어 안내, `README.setup.md`는 PyPI 설명에 사용하는 간결한 영어 문서로 다룬다.
- Windows 개발 환경에서는 VS Code가 지침을 검색하는 `.github/instructions`를 프로젝트 루트의 `instructions/`를 가리키는 디렉터리 정션으로 연결할 수 있다. 지침 원본은 루트 `instructions/`에 둔다.
- 디렉터리 정션은 Git에서 일반 디렉터리처럼 보이며 링크 자체를 이식 가능한 형태로 추적할 수 없다. `.github/instructions/`는 중복 파일이 변경 목록에 노출되지 않도록 제외하고, 새 체크아웃에서는 필요하면 정션을 다시 만든다.
- 루트의 `README.md`와 `README.en.md`에는 프로젝트 소개와 핵심 기능, 지원 환경·설치 및 최소 빠른 시작을 담고 `docs/README.md`로 안내한다. 전체 상세 매뉴얼을 복제하지 않는다.
- 루트의 `README.md`와 `README.en.md`에는 최신 버전 확인과 전체 변경 이력을 위한 릴리즈 페이지 링크를 제공한다. 릴리즈마다 수동 갱신이 필요한 버전 번호를 본문에 중복 관리하지 않으며, 최신 버전을 표시한다면 릴리즈 기준 정보와 자동으로 동기화되는 방식을 사용한다.
- 루트 README에 주요 변경 사항을 요약할 필요가 있으면 간단한 안내만 제공하고, 전체 변경 내역은 릴리즈 페이지를 기준으로 한다. 릴리즈 이력을 README에 복제하지 않는다.
- 루트의 한국어·영어 README에서는 문서 언어에 맞는 독자가 상세 매뉴얼을 찾을 수 있도록 링크 문구와 위치를 명확히 한다. 상세 매뉴얼의 영어판을 별도로 둘지 여부는 실제 문서 범위가 정해질 때 결정한다.
- `README.setup.md`는 패키지 소개, 요구 사항·설치와 빠른 시작을 중심으로 독립적으로 이해할 수 있게 작성하고, 외부 URL이나 외부 웹 페이지 링크를 넣지 않는다.
- `README.setup.md`에는 외부 링크 금지 규칙에 따라 릴리즈 페이지 링크를 추가하지 않는다.
- 공개 기능, 설치 옵션과 빠른 시작 예제는 현재 공개 API 및 실제 동작과 일치해야 한다.

### INS-02. 상세 매뉴얼 지침

- `instructions/DOCS.instructions.md`에 `docs/` 상세 매뉴얼의 구조와 작성 규칙을 정의한다.
- 상세 매뉴얼은 한국어와 영어로 모두 제공한다. 한국어 문서의 영어판은 동일한 파일명에 `.en.md`를 붙이고, 구조와 내용 범위를 맞추어 서로 연결한다.
- 초보 학생도 이해하고 따라갈 수 있도록 기본 개념부터 단계적으로 설명하며, 생소한 용어는 쉽게 풀어 쓴다.
- 실행 절차, import·설정, 예제 코드와 기대 결과를 충분히 제공한다. 학습에 도움이 되는 경우 완전한 실행 흐름의 샘플 코드를 우선하며, 예제는 실제 API와 호환되고 실행 가능해야 한다.
- 처리 흐름, 생명주기와 구성 요소 관계 등 시각화가 이해를 돕는 주제에는 Mermaid 다이어그램을 적극적으로 활용하고 충분히 제공한다. 다이어그램은 실제 동작에 맞게 작성하며, 초보자가 이해하도록 본문 설명을 함께 둔다.
- 한국어·영어 문서에서 같은 다이어그램을 제공할 경우 노드 표현은 문서 언어에 맞추되 구조와 의미를 일치시킨다. 장식용 다이어그램은 피하고 복잡하면 적절히 분리한다.
- 작업 완료 전 상세 매뉴얼에 반영할 사용자 영향 변경이 있는지 검토한다. 해당 변경이 있으면 한국어 매뉴얼과 대응 영어판을 함께 갱신하고, 변경 로그 작성 후 양쪽 내용의 일치 여부를 확인한다.
- 사용자 문서에 영향이 없는 내부 작업은 매뉴얼을 억지로 갱신하지 않고, 영향이 없다는 검토 결과를 작업 기록에 남긴다.
- `docs/README.md`를 한국어 진입점으로 작성하고, 처음에는 여기에 상세 내용을 둔다. 내용이 많아져 탐색이나 유지보수가 어려워지면 주제별 Markdown 파일로 분리한다.
- 분리된 각 문서는 한국어·영어 진입 문서에서 설명과 상대 링크로 연결한다. 실제 문서·기능에 근거해 작성하고 같은 상세 내용을 중복하지 않는다.
- 지침은 향후 매뉴얼 작성 규칙을 정의하는 범위이며, 이번 이슈에서 실제 README나 상세 매뉴얼을 작성하지 않는다.

| AC-08 | 실제 README나 상세 매뉴얼을 만들지 않고, 관련 워크플로 검증이 통과한다. |
