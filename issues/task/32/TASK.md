# CI 실행 정책 조사 및 로컬 검증 작업 기록

## 목적

[요구사항](./REQUIREMENTS.md)과 [계획](./PLAN.md)에 따라 기존 CI 계약과 영향 범위를 확인하고 구현 전후의 검증 근거를 확보했다.

## 수행 내용과 결과

### 기존 상태 확인

- 작업 브랜치가 `task/32`이며 구현 시작 시 작업 트리에 기존 미커밋 변경이 없음을 확인했다.
- DefEssential의 동일 목적 작업과 DefStream 워크플로를 비교했다.
- PR 대상 브랜치 제한, 경로별 테스트 생략, PR의 릴리즈 준비 의존성을 확인했다.
- 워크플로 단계 이름과 환경변수 참조를 조사하여 공통·RabbitMQ·Redis 회귀 테스트 세 파일이 함께 영향을 받는 것을 확인했다.
- 구현 전 해당 테스트 68개가 통과했다.

### 검증 환경

- 터미널 Python에서 PyYAML import가 `ModuleNotFoundError`로 실패했다.
- 누락 확인 후 YAML 정적 검증용으로 PyYAML 6.0.3을 해당 환경에 설치했다. 프로젝트의 런타임·테스트 의존성에는 추가하지 않았다.
- `BaseLoader`로 `on` 키를 문자열로 읽어 이벤트·job·step 조건을 검사했다.
- 변경한 Python 파일 세 개는 Pylance 구문 검사에서 오류가 없었다.

### 검증 결과

- 변경 후 관련 회귀 테스트 71개가 통과했다.
- 기존 HEAD와 변경 후 YAML 구조를 비교하여 테스트 job의 매트릭스·서비스·검증 단계와 배포 job의 보존을 확인했다.
- 이벤트·릴리즈 조건, artifact 대상과 필수 job 의존성 assertion을 통과했다.
- `git diff --check`를 통과했다.

## 운영 확인 대기

- GitHub Actions 실제 PR·push 이벤트와 fork 승인 동작을 실행하지 않았다.
- 서비스 통합·패키지 빌드·설치·UI 검증 전체를 로컬에서 실행하지 않았다.
- 원격 push, PR 생성, 태그 기록, PyPI 업로드와 GitHub Release 변경을 수행하지 않았다.
- 원격에서 확인할 시나리오와 인수 기준별 남은 항목은 [구현 기록](./IMPLEMENTS.md)에 정리했다.
