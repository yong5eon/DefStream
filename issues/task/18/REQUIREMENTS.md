# 변경 제안 및 핫픽스 이슈 양식 요구사항

## 목적

가벼운 변경과 핫픽스의 목적, 제안 내용 및 영향 범위를 GitHub Issue에서 간단히
정리할 수 있도록 별도 이슈 양식을 제공한다.

## 요구사항

- `.github/ISSUE_TEMPLATE/03.fix.yml`에 한국어 GitHub Issue Form을 추가한다.
- 이슈 제목 접두어는 지정하지 않고, 양식 이름은 `변경 제안`으로 표시한다.
- 요청 유형으로 `가벼운 변경`과 `핫픽스`를 선택할 수 있어야 한다.
- 변경 목적과 제안 내용을 필수로 수집하고, 영향 범위·핫픽스 긴급 정보·완료 기준은 선택 입력으로 제공한다.
- 기존 버그/오류 제보와 기능 제안 양식은 수정하지 않는다.

## 완료 기준

- 양식 YAML을 파싱할 수 있고 GitHub Issue Form 필수 항목을 포함한다.
- 일반 변경과 핫픽스에 필요한 정보를 각각 무리 없이 작성할 수 있다.
- 기존 작업 중인 이슈 양식 파일 이름 변경은 보존한다.

## 소스 코드 외 작업 양식

- `.github/ISSUE_TEMPLATE/04.task.yml`에 리소스 변경, 문서화 등 소스 코드 변경이
  아닌 작업을 정리하는 한국어 GitHub Issue Form을 추가한다.
- 양식 이름은 `작업 제안`으로 하고, 이슈 제목 접두어는 지정하지 않는다.
- 작업 목적, 작업 내용과 대상, 완료 기준은 필수 입력으로 제공한다.
- 관련 자료와 주의사항은 선택적으로 작성할 수 있도록 한다.
- 기존 이슈 양식은 변경하지 않으며, YAML 구조와 필수 항목·필드 ID를 검증한다.

## 이슈 레이블 자동 지정

- 기능 제안, 버그/오류 제보, 변경 제안, 작업 양식의 `labels`에 각각
  `feature`, `bug`, `fix`, `task`를 지정한다.
- 기존 제목과 입력 항목은 유지한다.
- GitHub 저장소에 같은 이름의 레이블이 미리 있어야 하며, 양식 설정 자체가
  레이블을 생성하지 않는다는 점을 안내한다.

## GitHub 양식 유효성

- 제목 접두어를 사용하지 않으면 선택 항목인 `title`을 생략한다.
  GitHub에서 허용하지 않는 빈 문자열을 명시하지 않는다.
- 번호가 포함된 기존 파일명과 레이블·입력 항목은 유지한다.

## PR 테스트 실행 범위 및 디렉터리 정리

- DefStream의 `test` 디렉터리를 `tests`로 변경하고 CI 및 관련 경로 참조를 갱신한다.
- 변경 중인 `samples` 디렉터리 이름을 유지하고 샘플 테스트와 문서 링크를 맞춘다.
- PR에서는 `samples/`, `src/`, `tests/` 아래 파일 또는 루트 `setup.py`의 추가·변경·삭제가 있을 때만
  Python 테스트 매트릭스 및 UI 테스트를 실행한다.
- 문서·이슈 양식만 변경하는 PR은 테스트 작업을 건너뛴다. 워크플로 자체는
  실행하여 기존 버전 계획·변경 로그 검사를 유지한다.
- master push의 테스트·배포 및 외부 어댑터 저장소의 기존 테스트 경로는 유지한다.

## 영어 사용 설명서 동기화

- 한국어 README를 기준으로 영어 README의 절 구성, 예제 및 주의사항을 맞춘다.
- 축약되어 한국어 안내로 연결되던 로깅 절을 전체 영어 설명과 동일 예제로 대체한다.
- 영어 목차에 로깅을 추가하며, 언어 선택 링크를 제외한 한국어 설명은 남기지 않는다.
