# 변경 제안 및 핫픽스 이슈 양식 구현 기록

## 구현 내용

[요구사항](./REQUIREMENTS.md)에 따라
[03.fix.yml](../../../.github/ISSUE_TEMPLATE/03.fix.yml)을 추가했다.
요청자가 가벼운 변경과 핫픽스를 구분하고, 목적과 변경 내용은 필수로,
영향 범위·긴급 배경·완료 기준은 필요한 경우 선택적으로 작성하도록 구성했다.
기존 버그/오류 제보와 기능 제안 양식은 변경하지 않았다.

## 검증

Python 가상환경의 PyYAML로 양식 YAML을 파싱하고, 필수·선택 필드와 필드 ID의
중복 여부를 확인했다. `git check-ignore`에서 새 양식이 제외되지 않는 것과
`git diff --check`를 확인했다. GitHub 웹 UI 렌더링은 확인하지 않았다.

## 소스 코드 외 작업 양식

[04.task.yml](../../../.github/ISSUE_TEMPLATE/04.task.yml)에 리소스 변경과
문서화 등 소스 코드 변경이 아닌 작업을 위한 양식을 추가했다.
작업 목적, 작업 내용 및 대상, 완료 기준은 필수로 작성하며 관련 자료 및
주의사항은 선택적으로 작성할 수 있다. 기존 이슈 양식은 수정하지 않았다.

PyYAML로 YAML 구문, 양식 이름·제목, 필수 입력 항목과 필드 ID 중복 여부를
검증했다. 새 파일의 Git 제외 여부 및 공백 검사와 `git diff --check`도 통과했다.
GitHub 웹 UI에서의 양식 렌더링은 확인하지 않았다.

## 이슈 레이블 자동 지정

네 이슈 양식의 최상위 `labels` 배열에 각각 `feature`, `bug`, `fix`, `task`를
지정했다. 사용자가 수정한 빈 제목과 기존 입력 항목은 유지했다.
저장소에 레이블이 미리 존재해야 한다는 운영 조건은 [변경 로그](./README.md)에
명시했다. 원격 저장소의 레이블 생성이나 존재 여부 확인은 수행하지 않았다.

PyYAML로 네 파일의 레이블 배열이 지정된 이름 하나만 포함하는지, 빈 제목과
필드 ID 중복 없음이 유지되는지 검증했다. `git diff --check`도 통과했다.

## 양식 선택 화면 미표시 수정

GitHub 공식 유효성 문서는 문자열 항목에 빈 문자열을 허용하지 않으며,
선택 항목은 값을 비우는 대신 항목 자체를 생략하도록 안내한다.
네 양식의 `title: ""`를 제거하여 제목 접두어 없이 작성하는 의도를 유지했다.
번호가 포함된 파일명, 레이블과 입력 항목은 변경하지 않았다.
앞선 YAML 구문 검증은 이 GitHub 제약을 확인하지 못했다.

공식 근거: [Issue Forms 유효성 오류](https://docs.github.com/en/communities/using-templates-to-encourage-useful-issues-and-pull-requests/common-validation-errors-when-creating-issue-forms).
로컬 검증에서 네 양식의 빈 최상위 문자열 없음, `title` 생략, 레이블 매핑과
입력 필드 ID를 확인했다. GitHub 화면에서의 복구 확인은 수행하지 않았다.

### 작업 양식만 누락되는 현상

원격 기본 브랜치에도 네 양식과 `title` 제거가 반영된 것을 GitHub API로 확인했다.
다른 양식은 표시되지만 작업 양식만 보이지 않는다는 사용자 확인에 따라,
짧은 표시 이름의 영향을 점검하기 위해 `name`을 `작업`에서 `작업 제안`으로
변경했다. 파일명, 레이블과 입력 항목은 유지했다.
공식 문서에서 이름의 최소 길이 제한은 확인하지 못했으므로 원인 확정이나
GitHub 화면에서의 복구 완료로 간주하지 않는다.

## PR 테스트 경로 조건 및 디렉터리 이전

- `changes` 작업에서 PR의 base와 head 사이 변경을 merge-base 기준으로 확인하고,
  `samples/`, `src/`, `tests/` 또는 루트 `setup.py` 변경이 있을 때만 `test_required=true`를 출력한다.
  이름 변경을 삭제·추가로 취급하므로 대상 경로 밖으로 옮겨진 파일의 삭제도 감지한다.
- 테스트 작업 전체에 조건을 적용해 Python 매트릭스, 브로커 서비스와 Node UI
  테스트를 함께 건너뛴다. master push에서는 항상 테스트를 수행하므로
  배포 산출물 생성·검증·게시 흐름은 바뀌지 않는다.
- 코어 `test`를 `tests`로 이전하고 CI의 unittest·Node 경로를 갱신했다.
  외부 RabbitMQ·Redis 저장소를 체크아웃할 때는 기존 `test` 경로를 유지한다.
- 사용자가 진행 중인 `sample` → `samples` 이전은 보존하고 샘플 테스트의 경로와
  한영 README 및 기존 작업 문서의 상대 링크를 맞췄다.
- CI 회귀 테스트에서 문서 전용 PR의 테스트 생략, 대상 경로 변경, push의 항상
  실행, 실제 Git 경로 필터 및 샘플 삭제 감지를 검증한다.

### 검증 결과

- VS Code 테스트 도구가 테스트를 찾지 못해 가상환경의 unittest로 실행했다.
- CI 회귀 및 로깅 테스트: 34개 통과.
- `python -m unittest discover -s tests`: 총 205개 중 197개 통과, 8개 건너뜀.
  브로커 실서버 통합 검증 결과로 간주하지 않는다.
- 수정 Python 테스트 두 파일의 Pylance 문법 검사와 `git diff --check` 통과.
- Node 실행 파일이 PATH와 표준 설치 위치에 없어 UI 테스트는 실행하지 못했다.
  GitHub Actions에서의 조건부 실행 및 배포 자체는 로컬에서 확인하지 않았다.

### setup.py 변경 감지 및 영어 README 동기화

- 설치·패키징 변경도 PR 테스트를 실행하도록 경로 조건에 루트 `setup.py`를
  추가했다. 실행 결과 회귀 테스트와 실제 Git 경로 선택 테스트도 함께 갱신했다.
- 영어 README의 한국어 로깅 요약을 한국어판과 같은 전체 영어 설명 및 설정
  예제로 대체하고 목차에 로깅 링크를 추가했다. 로거 이름·레벨, 핸들러 필터,
  민감정보, `lastResort` 및 ProcessPool 자식의 초기화 주의사항을 맞췄다.
- 두 README 전체 절을 대조했다. 코드 예제 14개는 주석 번역을 제외하면 동일하며,
  절 구성도 대응한다. 영어판에는 언어 선택 링크 외 한국어가 남지 않았고,
  로컬 파일 링크와 목차 앵커도 확인했다.
- CI 회귀 테스트 24개, 변경 테스트 파일의 Pylance 문법 검사, 워크플로 YAML
  파싱과 `git diff --check`를 통과했다. 기존 테스트 도구가 테스트를 찾지 못해
  가상환경의 unittest로 실행했다. GitHub Actions 실행은 수행하지 않았다.
