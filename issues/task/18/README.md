# 변경 제안 및 핫픽스 요청

기여자는 새 변경을 제안할 때 `변경 제안` 이슈 양식을 사용해 일반 변경 또는
핫픽스를 선택하고, 목적과 제안 내용을 기록할 수 있습니다. 핫픽스라면 긴급한
이유와 영향을 받는 버전도 함께 적을 수 있습니다.

재현 가능한 기존 결함은 기존 버그/오류 제보 양식을 이용하세요.
자세한 양식 기준은 [요구사항](./REQUIREMENTS.md)을 참고하세요.

## 리소스 변경 및 문서화 작업

소스 코드 변경 없이 리소스를 변경하거나 문서를 작성·정리할 때는 `작업 제안`
이슈 양식을 사용할 수 있습니다. 작업 목적, 대상과 내용, 완료 기준을 작성하고
필요하면 참고 자료와 주의사항을 덧붙이세요.

## 이슈 자동 분류

각 양식으로 이슈를 만들면 기능 제안은 `feature`, 버그/오류 제보는 `bug`,
변경 제안은 `fix`, 작업은 `task` 레이블이 자동으로 지정됩니다.
저장소 관리자는 GitHub 저장소의 Issues → Labels에서 해당 이름의 레이블을
미리 만들어 두어야 합니다. 양식은 레이블을 새로 생성하지 않습니다.

## PR 테스트 실행 범위

PR의 Python·UI 테스트는 `samples/`, `src/`, `tests/` 아래 또는 루트 `setup.py`에 변경이 있을 때만
실행됩니다. 문서나 이슈 양식만 변경하면 테스트 작업은 건너뛰지만,
기존 버전 계획과 변경 로그 검사는 계속 실행됩니다.
master push의 테스트·배포 절차는 유지합니다.

코어 테스트 디렉터리는 `test`에서 `tests`로 변경했습니다.
저장소 루트에서 `python -m unittest discover -s tests`로 실행할 수 있습니다.
샘플 경로는 `samples/`를 사용합니다.

## 영어 안내 동기화

영어 README에 한국어 README와 동일한 로깅 설정 예제, 로거별 레벨과 범위,
민감정보 주의사항 및 ProcessPool 자식 프로세스 설정 안내를 제공합니다.
