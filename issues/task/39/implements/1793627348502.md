# 코어·브로커 CI job 분리

GitHub Actions의 `test` job에서 RabbitMQ·Redis 컨테이너 실행과 브로커 통합 테스트를 제거하고, `tests/` 루트의 Python 테스트 모듈만 실행하도록 전용 runner를 추가했다. 이 runner는 저장소 루트의 `test_*.py` 모듈만 명시적으로 불러와 하위 디렉터리의 브로커 테스트가 코어 job에 포함되지 않게 한다.

`test-rabbitmq`와 `test-redis` job을 각각 추가했다. 각 job은 해당 브로커 전용 테스트 디렉터리를 실행하며, 지원 버전 두 개와 Python 3.9~3.14의 곱집합을 매트릭스로 구성했다. RabbitMQ job은 각 컨테이너의 필수 플러그인도 검사하고, 두 job 모두 `always()` 정리 단계에서 해당 Compose 파일의 컨테이너만 종료한다. 릴리스 publish job은 새 테스트 job 둘의 성공도 필요로 한다.

CI의 실행 구성은 코어 6개 조합, RabbitMQ 12개 조합, Redis 12개 조합이다. 로컬에서 코어 테스트 207개, RabbitMQ 테스트 71개(7개 skip), Redis 테스트 32개(8개 skip)가 각각 통과했다. 실제 브로커 버전별 실행은 Docker 엔진이 없어 로컬에서 검증하지 못했다. 자세한 결과는 [테스트 기록](../tasks/1793627348502.md)을 참고한다.
