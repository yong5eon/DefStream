# 버전별 RabbitMQ·Redis 테스트 환경 추가

`res/docker/rabbitmq/`에 3.13과 4.4 Compose 파일을 추가하고 `enabled_plugins`를 읽기 전용으로 마운트해 `rabbitmq_management`, `rabbitmq_prometheus`, `rabbitmq_shovel`, `rabbitmq_shovel_management`를 활성화했다. `res/docker/redis/`에는 Redis 6.2와 7.4 Compose 파일을 추가했다. 네 설정은 서로 다른 Compose project 이름과 고정 컨테이너 이름을 사용하며, 호스트 loopback에만 버전별 포트를 게시하고 각 브로커의 준비 상태를 health check로 확인한다.

`tests/_support.py`에 RabbitMQ·Redis 포트를 환경변수에서 읽는 함수를 추가하고, 관련 테스트가 해당 함수를 사용하도록 연결했다. 환경변수가 없으면 기존 포트 `5672`와 `6379`를 유지하므로 기존 로컬 테스트 실행 방식도 그대로 사용할 수 있다.

GitHub Actions의 기본 테스트 job은 RabbitMQ 4.4·Redis 7.4 Compose 환경을 사용하고, 별도 호환성 job은 RabbitMQ 3.13·Redis 6.2를 대상으로 한다. 두 job 모두 브로커 준비를 기다린 뒤 네 RabbitMQ 플러그인을 확인하고, 완료·실패 여부와 관계없이 자신이 생성한 브로커 컨테이너만 정리한다. 배포 job은 두 테스트 job의 성공을 모두 요구한다.

실행 방법과 포트는 [RabbitMQ 안내](../../../../res/docker/rabbitmq/README.md)와 [Redis 안내](../../../../res/docker/redis/README.md)에 각각 정리했다. 정적 검증·단위 테스트 결과와 실제 컨테이너 검증 제한은 [작업 기록](../tasks/1793623390265.md)에 정리했다. Docker 엔진이 실행되지 않아 컨테이너 기반 검증은 남아 있다.
