# Docker 구성과 테스트 검증

네 Compose 파일을 `docker compose config --format json`으로 검사했다. RabbitMQ 3.13·4.4, Redis 6.2·7.4 이미지, 서로 분리된 Compose project 이름, 요청한 컨테이너 이름과 loopback 포트가 예상대로 출력됐다. RabbitMQ `enabled_plugins` 설정 파일의 네 플러그인 항목과 Compose bind mount도 확인했다.

GitHub Actions 워크플로를 PyYAML로 파싱했고, 변경된 Python 모듈의 `py_compile`과 `git diff --check`를 통과했다. 관련 테스트 모듈은 `python -m unittest discover -s tests -p '<pattern>'`으로 총 153개를 실행했다. Inspector 45개(4개 건너뜀), RabbitMQ 관련 61개(3개 건너뜀), Redis 4개(4개 건너뜀), specification 29개(1개 건너뜀), task message 14개(3개 건너뜀)로 최종 실행에서 실패 없이 통과했다. 브로커 통합 테스트는 로컬 브로커가 없어 건너뛰었다. Inspector의 첫 실행은 Windows 기본 `cp949`가 기존 출력 문자를 인코딩하지 못해 실패했고, UTF-8 재실행 중 한 차례 발생한 소켓 연결 중단도 해당 테스트 단독 재실행과 전체 모듈 재실행에서 재현되지 않았다.

Docker 엔진 확인은 `docker info`에서 Docker Desktop Linux 엔진 named pipe에 연결할 수 없다는 오류로 실패했다. 따라서 이미지 pull, 컨테이너 기동, health check, 실제 RabbitMQ 플러그인 상태와 RabbitMQ·Redis 통합 동작은 로컬에서 검증하지 못했다. GitHub Actions에는 두 버전 조합의 기동 대기, RabbitMQ 플러그인 확인, 테스트 실행과 `always()` 정리를 추가했지만 원격 실행 결과는 아직 없다.
