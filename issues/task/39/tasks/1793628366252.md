# Docker 기반 브로커·Python 통합 테스트

네 Compose 환경을 실제로 기동했다. RabbitMQ 3.13.7·4.4.0, Redis 6.2.24·7.4.12 컨테이너가 모두 `healthy` 상태였고, RabbitMQ 양쪽에서 `rabbitmq_management`, `rabbitmq_prometheus`, `rabbitmq_shovel`, `rabbitmq_shovel_management`가 실행 중임을 확인했다.

로컬에 설치된 Python 3.9.13, 3.10.11, 3.12.10, 3.14.5를 사용해 브로커 버전 × Python 버전 조합 16개를 실행했다. 각 조합에서 RabbitMQ 테스트 71개와 Redis 테스트 32개가 모두 통과했다.

| Python | RabbitMQ 3.13.7 | RabbitMQ 4.4.0 | Redis 6.2.24 | Redis 7.4.12 |
| --- | --- | --- | --- | --- |
| 3.9.13 | 71 통과 | 71 통과 | 32 통과 | 32 통과 |
| 3.10.11 | 71 통과 | 71 통과 | 32 통과 | 32 통과 |
| 3.12.10 | 71 통과 | 71 통과 | 32 통과 | 32 통과 |
| 3.14.5 | 71 통과 | 71 통과 | 32 통과 | 32 통과 |

최초 RabbitMQ 4.4 실행에서는 통합 테스트가 만든 transient non-exclusive 큐가 브로커에 의해 거부되어 4개 테스트 오류가 발생했다. 제품 기본값과 동일하게 테스트 큐를 durable하게 선언하도록 수정한 뒤 전체 RabbitMQ 테스트를 재실행해 통과했다. 변경 내용은 [구현 기록](../implements/1793628366252.md)에 설명했다.

Python 3.11과 3.13은 로컬 설치본이 없어 실행하지 못했다. 따라서 CI에서 구성한 전체 Python 3.9~3.14 매트릭스 중 해당 두 버전의 실제 브로커 테스트 결과는 CI 실행을 통해 확인해야 한다. 검증 후 이번에 기동한 네 Compose 컨테이너는 각각 `down`으로 정리했다.
