# 브로커별 테스트 분리와 검증

코어 테스트를 `tests/` 루트에 남기고 RabbitMQ·Redis 전용 테스트를 각각 `tests/rabbitmq/`, `tests/redis/`로 이동했다. `tests/__init__.py`를 추가하고 지원 모듈과 공유 테스트 픽스처 import를 `tests.*` 경로로 바꿔, `redis`라는 로컬 폴더가 외부 Redis 클라이언트 패키지를 가리지 않도록 전체 discovery를 `python -m unittest discover -s tests -t .`로 실행하게 했다. 이동한 RabbitMQ·Redis 로그 테스트의 샘플 파일 참조도 프로젝트 루트 기준으로 수정했다.

RabbitMQ 전용 discovery는 71개 테스트 중 7개를 건너뛰고 통과했고, Redis 전용 discovery는 32개 중 8개를 건너뛰고 통과했다. 메시지 테스트 11개(브로커 통합 3개 건너뜀), 명세 테스트 28개, RabbitMQ·Redis 로그 테스트 26개, 코어 Inspector·Play·runner hook 테스트 40개도 통과했다. Windows 기본 `cp949` 콘솔에서는 worker 시작 배너가 인코딩 오류를 일으켜 UTF-8 콘솔로 재실행했으며, 두 Compose 안내에 PowerShell 환경 설정을 추가했다.

UTF-8 콘솔에서 전체 discovery는 310개 테스트를 실행해 15개를 건너뛰었고, `test_broker_packaging`에서 2개 오류와 2개 실패가 남았다. 이 테스트들은 현재 로컬 editable 설치의 배포 메타데이터와 패키지 레이아웃이 맞지 않는 환경 문제로 확인되어 수정하지 않았다. 테스트 Python 파일 컴파일, CI YAML 파싱, `git diff --check`는 통과했다.

Docker Desktop 엔진을 사용할 수 없어 실제 컨테이너 및 브로커 통합 테스트는 실행하지 못했다. CI workflow에 등록한 원격 검증 결과도 아직 확인하지 않았다.

테스트 구조 변경의 상세 내용은 [구현 기록](../implements/1793625464717.md)에 정리했다.

## CI 테스트 탐색 추가 확인

CI의 설치 패키지 테스트는 저장소 외부 디렉터리에서 테스트 파일을 절대 경로로 찾지만 `top_level_dir`를 지정하지 않았다. 같은 작업 디렉터리 조건으로 확인했을 때 RabbitMQ·Redis 하위 테스트의 `tests.*` 지원 모듈 import와 `tests/redis` 이름 충돌 때문에 메시지 테스트 3개가 import 오류로 끝났다. CI 명령에 `-t "$GITHUB_WORKSPACE"`를 추가했다. 수정된 실행 조건으로 전체 310개 테스트가 import 오류 없이 발견되는 것을 확인했고, 같은 조건의 메시지 테스트 11개 실행도 통과했다(브로커 통합 테스트 3개는 선택 실행이 아니라 건너뜀).
