# 변경 로그 검사 순서와 형식 판단

## 상황과 근거

[후속 계획](../PLAN.md)에 따른 테스트에서 들여쓴 마지막 목록 항목이 경로 선택 단계에 도달하는 것을 확인했다. 기존 PR 생성기는 일반 파일을 가리키는 심볼릭 링크를 따라 PR 생성 요청까지 진행했다.

## 결정과 영향

CI는 감지 시 들여쓰기를 제거하지만 형식 검증에는 원래 줄을 사용한다. PR 생성기는 변경 로그를 읽기 전에 `lstat`로 링크 자체가 일반 파일인지 확인한다. 이는 링크가 읽을 수 없는 대상을 가리켜도 파일을 열기 전에 거부하기 위한 순서다. 없는 파일의 기존 오류와 네 칸·탭 들여쓰기의 폴백은 유지한다. 회귀 검증 결과는 [작업 기록](../tasks/1794083646073.md)에 남겼다.

네 칸 이상이나 탭으로 들여쓴 마지막 줄은 현재 코드가 문맥을 구분하지 않고 코드 블록으로 취급한다. 이 줄도 Markdown 중첩 목록일 수 있다. 사용자가 패턴 추출에 구조 구분이 필요한지 의문을 제기해, 에이전트는 파서를 추가하지 않고 기존 폴백과 이 한계를 유지하기로 판단했다.
