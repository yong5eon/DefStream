# 요구사항 명세서

## 목적

GitHub 이슈 [#36](https://github.com/yong5eon/DefStream/issues/36)에 따라 DefStream의 상세 사용 매뉴얼과 프로젝트 루트 README를 작성한다. 한국어 문서를 기준으로 영어 문서를 함께 제공해 처음 사용하는 독자와 패키지 설치 환경에서 필요한 정보를 찾을 수 있게 한다.

## 범위

### 포함

- 상세 매뉴얼 진입 문서 `docs/README.md`와 `docs/README.en.md`
- 필요한 주제별 한국어 매뉴얼과 각 영어 대응 문서
- 프로젝트 소개와 빠른 시작을 제공하는 `README.md`, `README.en.md`
- 패키지 저장소에서 독립적으로 읽을 수 있는 영어 `README.setup.md`
- 매뉴얼 및 README의 내부 링크, 언어별 대응 관계, 안내 내용의 정확성 검증

### 제외

- 제품 코드, 공개 API, 패키지 설정과 동작 변경
- 이슈에서 지정하지 않은 독립적인 기능 추가나 리팩터링
- DefEssential 저장소의 문서 작업(별도 이슈 #19에서 다룸)
- 프로젝트 전체 릴리즈 변경 로그 갱신

## 요구사항

### 상세 매뉴얼

- 상세 매뉴얼은 저장소 루트의 `docs/`에 둔다.
- `docs/README.md`를 한국어 진입 문서로, `docs/README.en.md`를 영어 진입 문서로 작성한다.
- 두 진입 문서는 주제별 안내와 목차의 범위를 맞추고 서로 연결한다.
- 주제별 문서는 학습과 탐색에 실질적인 이점이 있을 때만 분리한다. 한국어 주제 문서에는 같은 이름의 `.en.md` 영어 문서를 제공하고, 양쪽 진입 문서에서 대응하는 주제를 안내한다.
- 아직 작성하지 않은 주제의 빈 문서나 형식적인 목차 항목은 만들지 않는다.
- 초보 독자가 따라갈 수 있도록 사전 조건, 개념, 단계별 절차, 실행·확인 방법을 설명한다. 필요한 경우 현재 API와 호환되는 완결된 예제, 실행 방법과 기대 결과를 포함한다.
- 설치와 빠른 시작부터 작업 정의·메시지 처리, 실행 풀과 종료, 생명주기 훅, 계약·검증, Inspector 및 운영 기능, 로깅, RabbitMQ·Redis 사용과 운영상 주의사항까지 공개 기능 중 사용자 안내가 필요한 범위를 다룬다.
- 설정, 코드 예제, 기능 설명과 제약은 실제 공개 API와 구현에 근거해야 한다. 외부 브로커가 필요한 안내는 전제 조건을 밝히며, 확인되지 않은 기능이나 보장을 사실처럼 기술하지 않는다.
- 흐름이나 구성 요소 관계가 이해에 도움이 되는 주제에는 실제 동작과 일치하는 Mermaid 다이어그램을 포함한다. 다이어그램만으로 절차나 계약을 대체하지 않는다.

### 루트 README

- `README.md`는 한국어, `README.en.md`는 영어로 DefStream의 목적과 핵심 기능, 설치 및 최소 빠른 시작을 안내한다.
- 두 README는 주요 기능, 설치 방법과 빠른 시작의 범위를 맞추고 서로 연결한다.
- 프로젝트 루트 README의 영어 서브타이틀과 슬로건은 의도된 문구이므로 한국어 README에서도 번역·수정하지 않고 영어 원문 그대로 유지한다.
- Python 요구 사항, 기본 설치와 RabbitMQ·Redis 선택 extra, 코드 예제의 API·import 경로, 브로커 실행 전제 조건은 프로젝트 설정과 실제 동작에 맞춘다.
- 두 README에서 상세 매뉴얼 진입점인 `docs/README.md`로 각각 연결한다. 영어판 매뉴얼 진입 문서인 `docs/README.en.md`도 찾을 수 있도록 안내한다.
- 상세 매뉴얼 전체를 루트 README에 복제하지 않는다.
- 두 README에서 DefStream 릴리즈 페이지를 안내해 최신 릴리즈와 전체 변경 이력을 찾을 수 있게 한다. 수동 갱신이 필요한 버전 번호를 중복 기재하지 않는다.

### 패키지용 README

- `README.setup.md`는 영어로 작성하며 프로젝트 목적, Python 요구 사항, 설치 방법과 최소 빠른 시작을 포함한다.
- 외부 URL이나 외부 웹 페이지 링크를 포함하지 않는다.
- 이 문서만 패키지 저장소에서 읽더라도 설치와 최소 사용에 필요한 전제 조건을 알 수 있어야 한다.

## 제약 및 호환성

- 문서 작성만 수행하며 제품 코드와 공개 동작은 변경하지 않는다.
- 문서 언어별로 같은 기능, 제약과 예제의 의미를 유지한다.
- 선택 의존성과 브로커별 전제 조건을 기본 설치에 포함된 것으로 오해하게 작성하지 않는다.
- 비밀값이나 실제 인증정보를 예제에 포함하지 않는다.
- 사용자에게 영향이 없는 내부 구현 세부사항을 고객 대상 README에 불필요하게 추가하지 않는다.

## 인수 기준

1. `docs/README.md`와 `docs/README.en.md`가 한국어·영어 매뉴얼 진입점으로 작성되고, 주제 구성과 링크 범위가 서로 일치한다.
2. 작성된 각 주제별 매뉴얼에 대응하는 영어 문서가 있으며, 설명·예제·제약이 언어 간에 일치한다.
3. 매뉴얼이 이슈에서 요구한 상세 사용 안내를 포함하고, 기술 설명과 예제가 현재 구현 및 공개 API와 일치한다.
4. `README.md`, `README.en.md`, `README.setup.md`가 각각 해당 문서 역할과 언어 요건을 충족한다.
5. 두 루트 README는 `docs/README.md`를 상세 매뉴얼 진입점으로 연결하고 영어 매뉴얼 진입점도 안내하며, `README.setup.md`에는 외부 링크가 없다.
6. 문서 내부 링크와 앵커가 실제 대상에 연결되고, Markdown 구조에 오류가 없다.
7. 제품 코드 변경 없이 문서 대상 파일만 변경되며, 검증 결과가 작업 기록에 구분되어 남는다.

## 확인이 필요한 사항

- 없음. 이슈의 범위와 프로젝트 문서 지침으로 문서 구조 및 언어 요건을 구체화했다.
