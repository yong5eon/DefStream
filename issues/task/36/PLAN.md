## 진행 원칙

- 공개 API와 구현을 확인하며 문서를 작성하고, 제품 코드 변경은 하지 않는다.
- 루트 README의 기존 설명과 예제를 검토해 상세 매뉴얼에 필요한 내용을 옮기거나 확장하되, 루트 README에는 프로젝트 개요와 빠른 시작을 남긴다.
- 한국어·영어 문서는 주제, 기능, 예제와 제약을 일치시킨다.
- 루트 README의 기존 영어 서브타이틀과 슬로건은 한국어 문서에서도 번역하거나 수정하지 않는다.
- `README.setup.md`는 패키지 메타데이터로 독립 배포되는 문서이므로 외부 링크를 두지 않는다.
- 진행 중 문서 구성이 요구사항과 달라지면 이 계획과 요구사항 명세를 함께 갱신한다.

| 2 | `docs/README.md`와 `docs/README.en.md`를 작성하고, 주제별 문서를 나누는 경우 한국어·영어 문서를 함께 작성한다. 각 문서에 초보자용 설명, 검증된 예제와 필요한 다이어그램을 포함한다. | 상세 매뉴얼 | 대기 |
| 3 | `README.md`와 `README.en.md`를 핵심 소개·설치·빠른 시작 중심으로 정리하고, 매뉴얼 진입점 및 릴리즈 페이지 링크를 추가한다. 기존 영어 서브타이틀과 슬로건은 그대로 보존한다. | 루트 README | 대기 |
| 4 | `README.setup.md`를 독립적인 영어 패키지 설명으로 점검·정리하고 외부 링크가 없는지 확인한다. | 패키지용 README | 대기 |
| 5 | 문서 쌍의 범위와 의미, 내부 링크·앵커, 설치 및 import 예제, Markdown 구조를 검증하고 실제 결과를 기록한다. 필요하면 발견한 문서 오류를 수정한 뒤 검증을 반복한다. | 인수 기준 전체 | 대기 |

## 인수 기준별 검증

| 인수 기준 | 검증 방법 |
| --- | --- |
| 한국어·영어 상세 매뉴얼 진입점과 주제 구성이 일치함 | 두 진입 문서의 주제 목록과 대응 링크를 대조한다. |
| 주제별 영어 문서와 한국어 문서의 내용이 일치함 | 주제별 문서 쌍의 기능, 예제, 제약 및 언어 간 링크를 검토한다. |
| 매뉴얼 설명과 예제가 구현 및 공개 API에 맞음 | 관련 소스, 공개 export, `setup.py`, 샘플과 문서 예제를 대조하고 실행 가능한 예제는 해당 환경에서 확인한다. |
| 루트 README 세 문서의 역할과 내용이 정확함 | 목적·기능·설치·빠른 시작을 검토하고 한국어/영어 README의 범위를 비교한다. |
| 매뉴얼·릴리즈 링크와 setup 문서 외부 링크 제한을 충족함 | 상대 링크 대상의 존재를 확인하고 `README.setup.md`에서 URL 및 외부 링크를 검사한다. |
| Markdown 구조와 내부 앵커가 올바름 | 저장소에 설정된 문서 검증 도구가 있으면 사용하고, 없으면 제목·코드 펜스·표·링크 및 앵커를 점검한다. |
| 제품 코드 변경 없이 대상 문서만 수정됨 | 완료 시 저장소 변경 목록을 확인해 문서 범위와 일치하는지 검토한다. |

## 선행 조건과 주의사항

- 현재 작업 브랜치는 `task/36`이다. 다른 저장소나 이슈의 변경을 포함하지 않는다.
- 병합 대상 브랜치는 지정되지 않았으므로 임의로 정하거나 실제 병합에 사용하지 않는다.
- 현재 `docs/` 디렉터리는 없으므로 필요한 문서만 새로 만든다. 형식적인 빈 주제 문서는 만들지 않는다.
- `README.setup.md`의 외부 링크 금지와 루트 README의 영어 서브타이틀·슬로건 보존을 모든 편집 단계에서 확인한다.
