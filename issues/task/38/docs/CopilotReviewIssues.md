# PR 리뷰 지적 이슈 등록

`.github/workflows/create-issues-from-reviews.yml`은 PR 리뷰가 제출될 때 해당 PR의 미해결 리뷰 스레드에서 조치가 필요한 최초 코멘트를 GitHub 이슈로 등록합니다. 리뷰 작성자와 리뷰 상태는 제한하지 않으며 PR 코드 승인은 필요하지 않습니다.

PR이 아직 없다면 `.github/workflows/create-pr-from-issue.yml`이 지원되는 이슈 브랜치의 push에서 PR을 만듭니다. 제목은 이슈 디렉터리 `README.md`의 유효한 첫 제목을 우선 사용하고, 없거나 길이 제한을 넘으면 원본 GitHub 이슈 제목을 사용합니다. 본문에는 `README.md`, `REQUIREMENTS.md`, `CHANGELOG.md`, `IMPLEMENTS.md`, `TASKS.md` 중 내용이 있는 문서만 전체 본문과 출처 링크로 반영합니다. 고정 섹션명을 요구하지 않으며 구현·작업 기록을 모두 작성할 필요도 없습니다. 문서가 모두 없거나 비어 있으면 원본 이슈 본문과 링크로 PR을 만듭니다.

`.github/PULL_REQUEST_TEMPLATE.md`가 있으면 사용하고, 안내 문구나 체크박스가 달라도 생성을 막지 않습니다. 필요한 본문은 템플릿 뒤에 추가하며, 템플릿 자체가 없어도 생성합니다. 본문이 65,536자를 넘으면 문서·이슈는 원문 링크로 제공하고 이유를 표시합니다. 템플릿만으로도 제한을 넘으면 템플릿도 원문 링크로 제공합니다. 검증 기록이 없다는 사실을 명시하며 검증 성공을 추측하지 않습니다. 파일 부재 외 읽기 오류와 GitHub API·권한 오류는 실패로 표시합니다.

커밋 메시지는 읽거나 비교하지 않습니다. 기본 브랜치가 PR 대상이며, 같은 head/base의 열린 PR이 있거나 base와 비교해 변경 파일이 없으면 새로 만들지 않습니다.

새 PR은 설치한 GitHub App의 bot이 작성합니다. PR 작성자와 관계없이 리뷰 제출이 실행 계기이며 기존 PR의 작성자는 변경되지 않습니다.

PR 본문에 문서의 치환 특수문자는 원문 그대로 삽입합니다. Markdown 링크·이미지의 상대 경로는 각 원본 문서와 push 커밋 SHA를 기준으로 GitHub 절대 URL로 변환하고, 외부 URL과 인라인·펜스 코드 예시는 유지합니다. 참조 링크는 문서의 참조 정의를 찾아 인라인으로 변환하며 저장소 밖으로 벗어나는 경로는 오류로 처리합니다. 이 변환은 새 PR 본문 생성에 적용되며 이미 열린 PR의 본문은 재작성하지 않습니다.

열린 PR이 없으면 기본 브랜치와 push 커밋을 비교합니다. squash 병합 이후 merge base 기준 변경 파일 목록이 남아 있어도 두 커밋의 tree SHA가 같으면 PR을 생성하지 않습니다. 비교는 이동 가능한 head 브랜치 대신 push SHA로 고정하며, 필요한 tree 조회·검증이 실패하면 Actions에서 오류를 표시합니다.

## PR 마일스톤 적용

작업 브랜치에 push하면 원본 GitHub 이슈의 마일스톤을 새 PR과 이미 열린 PR에 동일하게 지정합니다. 마일스톤 이름 대신 같은 저장소의 마일스톤 번호를 사용하며, PR에 다른 마일스톤이 있으면 원본 이슈 값으로 변경합니다.

- 원본 이슈에 마일스톤이 없으면 PR의 기존 값을 유지하며 마일스톤 수정 API를 호출하지 않습니다.
- 기존 App 토큰의 Issues 쓰기 권한을 사용하므로 workflow 권한이나 Secret을 추가할 필요가 없습니다.
- 조회 결과가 잘못되었거나 적용 API가 실패하거나 응답의 마일스톤 번호가 요청과 다르면 Actions 실행이 실패합니다. 이미 생성된 PR이나 앞서 적용한 레이블·담당자는 남을 수 있습니다. 권한과 원인을 해결한 뒤 workflow를 재실행할 수 있습니다.
- 이슈의 마일스톤만 수정하면 즉시 반영되지 않습니다. 다음 작업 브랜치 push 또는 해당 브랜치의 workflow 재실행 때 반영됩니다.
- 프로젝트 등록과 프로젝트 필드 값 복사는 수행하지 않습니다.

## Copilot 리뷰 요청 관리

PR 생성 workflow에서는 Copilot 리뷰 요청 API를 호출하지 않습니다. 리뷰가 필요하면 GitHub에서 수동 요청하거나 적용 가능한 자동 리뷰 설정을 사용합니다. 개인의 Automatic Copilot code review와 Review new pushes 설정이 App bot 작성 PR에도 적용되는지는 별도 확인해야 하며, 이 workflow에서 설정하거나 보장하지 않습니다.

## 처리 흐름

1. `pull_request_review.submitted` 이벤트에서 실행합니다. `commented`·`approved`·`changes_requested`를 구분하지 않으며 리뷰 작성자의 `author_association`으로 제한하지 않습니다.
2. GitHub 자체 실행 승인·권한 정책은 유지합니다. Actions 실행 승인과 PR의 코드 승인 리뷰는 별개이며 후자를 실행 조건으로 요구하지 않습니다.
3. PR 전체 리뷰 스레드의 해결 상태를 확인합니다.
4. `Unresolved` 스레드의 첫 번째 줄별 코멘트만 Copilot CLI에 전달합니다. `Resolved` 스레드, 스레드 답글과 리뷰 본문은 처리하지 않습니다.
5. 구체적인 후속 조치가 필요한 코멘트마다 이슈를 하나씩 등록합니다. 단순 요약·칭찬·질문은 제외합니다.
6. PR head 브랜치의 `{feature|bug|fix|task}/{이슈번호}`에서 부모 이슈를 확인하고, 새 이슈를 하위 이슈로 연결합니다.

Copilot 응답이 조치 가능한 지적을 반환하지 않으면 이슈를 만들지 않습니다. 리뷰 코멘트가 없거나 미해결 스레드의 최초 코멘트가 없는 경우도 등록하지 않습니다. 리뷰 스레드 상태 조회에 실패하면 전체 실행을 실패 처리하고, 상태를 확인하지 못한 코멘트는 분류하지 않습니다.

## 분류와 이슈 본문

- 기존 동작 결함은 `bug`, 결함 보고가 아닌 변경 제안은 `fix`로 분류합니다. 판단이 불명확하면 레이블을 붙이지 않습니다.
- `bug` 및 `fix` 이슈는 각각 [버그 양식](../../../../.github/ISSUE_TEMPLATE/02.bug.yml) 및 [변경 제안 양식](../../../../.github/ISSUE_TEMPLATE/03.fix.yml)의 항목 구조를 따르는 Markdown 본문을 사용합니다.
- 리뷰에 버전, 기대 동작, 재현 절차, 환경 등 양식 정보가 있으면 해당 항목에 반영합니다. 없는 정보는 만들어내지 않고 제공되지 않았다고 표시합니다. 분류가 불명확한 경우에는 문제·필요 조치·출처를 담은 공통 본문을 사용합니다.
- 양식 세부정보와 별도로 분류기가 정리한 문제와 필요한 조치도 본문에 포함합니다.
- 제목과 설명은 한국어로 작성하며 코드 식별자와 외부 API 이름은 원문 표기를 유지합니다.
- 본문에는 원본 PR·리뷰·코멘트 링크, 코드 파일·줄 위치, 부모 이슈 링크를 포함합니다.

GitHub Issue Form의 웹 입력 검증은 REST API 생성에 적용되지 않습니다. 이 자동화는 양식과 같은 섹션 구조로 Markdown 본문을 만들어 API에 직접 등록합니다.

## 중복 및 실패 동작

- 과거 이슈를 검색하거나 마커·유사도 기준으로 중복을 막지 않습니다.
- 워크플로를 다시 실행하거나 새 리뷰를 제출하면 같은 코멘트에 대한 이슈가 중복 생성될 수 있습니다. 중복은 사람이 정리합니다.
- 이슈 생성 후 부모 연결이 실패하면 워크플로는 실패하지만, 이미 생성된 이슈는 남을 수 있습니다. 재실행 전에 생성 결과를 확인하세요.
- Copilot CLI 요청, GitHub API, 부모 이슈 확인·연결 실패는 성공으로 처리하지 않고 Actions 실행을 실패 처리합니다.
- Copilot CLI가 실패하면 표준 오류의 앞부분을 최대 8 KiB까지 오류 로그에 포함합니다. App 토큰, Copilot 인증 토큰과 인식 가능한 GitHub 토큰 문자열은 로그 전에 가립니다.
- PR head 브랜치가 부모 이슈 규칙에 맞지 않거나 해당 번호가 PR이면 이슈를 생성하지 않습니다.

## 권한과 운영

GitHub API는 현재 저장소에 한정한 App 토큰을 사용합니다. PR 생성은 Contents 읽기, Issues 및 Pull requests 쓰기, 리뷰 이슈 등록은 Issues 쓰기 및 Pull requests 읽기 권한만 요청합니다.

checkout은 기본 `GITHUB_TOKEN`의 `contents: read`를 사용합니다. Copilot CLI는 `copilot-requests: write`를 가진 기본 토큰을 `COPILOT_GITHUB_TOKEN`으로 따로 전달받습니다. App 토큰을 Copilot 인증에 사용하지 않습니다. App 설치 및 변수·Secret 등록은 [설정 안내](./CopilotReviewIssuesSetup.md)를 참고하세요.

Copilot CLI는 도구를 비활성화한 상태로 리뷰 텍스트만 분석합니다. PR 코드나 리뷰의 명령을 실행하지 않습니다. 포크 PR의 토큰 권한 제한을 우회하지 않으며, 권한이 부족하면 실행이 실패합니다. Copilot CLI 정책과 사용량은 저장소 소유자 또는 조직 정책에 따릅니다.

Actions 실행 실패 원인은 해당 실행의 실패 단계와 로그에서 확인합니다. 기본 브랜치에서 자동화 테스트를 실행하려면 다음 명령을 사용합니다.

```shell
node --test .github/scripts/tests/create-pr-from-issue.test.mjs .github/scripts/tests/create-issues-from-reviews.test.mjs
```

실제 GitHub Actions 권한·인증·과금 및 쓰기 동작은 저장소 환경에서 별도로 확인해야 합니다.
