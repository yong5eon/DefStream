# Python 개발

## 코드 스타일

- PEP 8을 기본 스타일로 적용하지 않는다. 아래 규칙과 저장소의 기존 관례를 따른다.
- 클래스 이름은 PascalCase, 메소드와 멤버 변수 이름은 스네이크 케이스를 사용한다.
- 정정 함수는 스네이크 케이스를 사용한다.
- 상수는 대문자 SNAKE_CASE를 사용한다. 이름의 약어는 대문자로 표기한다.
- 프라이빗 메소드와 멤버 변수에도 선행 밑줄을 사용하지 않는다. `__init__` 같은 특수 메소드 이름은 그대로 사용한다.
- nullable 타입은 `Optional[T]`로 표기한다.
- 들여쓰기는 탭을 사용하고, 탭과 스페이스를 혼용하지 않는다.
- import 절의 대상, 클래스 선언의 상속 대상, 함수·메소드 시그니처의 매개변수, 리스트·튜플 등 컬렉션의 멤버가 2개 이상이면 반드시 멀티라인으로 작성하고 각 항목을 한 줄에 하나씩 배치한다.
- 여러 줄 import, 선언, 호출은 괄호나 해당 구문의 구분자를 사용해 읽기 쉽게 나누고 저장소의 기존 형식을 따른다.

## Import

- import는 기본적으로 모듈 최상위에 작성한다.
- 특별한 이유가 없으면 `import module` 대신 `from module import Class, function` 형식으로 필요한 클래스·함수 등을 직접 임포트한다. 대상이 2개 이상이면 위 멀티라인 규칙을 적용한다.
- 순환 참조 회피, 선택적 의존성, 플랫폼별 모듈 등 구체적인 필요가 있으면 함수 내부 import나 조건부 import를 허용한다.

## 클래스와 함수 문서화

- 공개 API, 복잡한 계약, 코드만으로 의도가 분명하지 않은 클래스·함수·메소드에는 독스트링을 작성한다.
- 독스트링의 여는 `"""`와 닫는 `"""`는 각각 별도 줄에 작성하고, 본문은 여는 구분자 다음 줄부터 작성한다. 한 줄 독스트링에도 같은 형식을 적용한다.
- 독스트링과 주석은 공통 지침에 따라 한국어로 작성한다.
- 생성·수정 이력은 주석으로 중복 기록하지 않고 버전 관리 이력을 사용한다.

## 타입 힌트

- 함수·메소드의 매개변수와 반환값에 타입 힌트를 작성한다. 호출 결과를 변수에 할당할 때도 `변수명: 반환타입 = 호출(...)` 형식으로 타입을 명시하여 받는 값의 계약을 분명히 한다.
- 타입은 호출 대상의 선언과 실제 반환 계약을 확인해 작성한다. 제네릭 타입은 원소·키·값 등의 타입 인자까지 명시한다.
- 반환값에서 사용하는 메소드도 해당 타입의 계약에 포함되어야 한다. 예를 들어 스트림의 `close()`를 호출한다면 `Iterator[T]`가 아니라 실제 반환 계약에 맞는 `Generator[T, None, None]` 또는 `close()`를 제공하는 타입인지 확인한다. 원소 타입도 실제 스트림 항목에 맞추며 임의로 `str`로 지정하지 않는다.
- 타입 힌트로 진단을 숨기기 위해 실제 계약과 다른 타입이나 `Any`, 근거 없는 `cast`를 사용하지 않는다. 반환 선언이 잘못되었거나 불충분하면 선언부를 확인하고 필요한 범위에서 바로잡는다.
